## 负责模块与已有资产的关系

| 内容 | 唯一负责模块 | 接线与限制 |
| --- | --- | --- |
| 身份、Session、成员、权限 | 既有本地身份负责模块 | 每次操作重查；任务 bearer 不构成用户身份 |
| 应用归属与生命周期 | 既有 Application Catalog | 精确应用 / 所有者；保存要求应用活跃，归档应用仍可读取自己的历史包 |
| 计划、授权、尝试终态 | `developmentcontrol` | 持久记录与不可变委托；完成不代表候选被用户接受 |
| 源码快照与测试事实 | `developmentsandbox` | 只读来源、私有候选、可信测试结果；关闭并确认所属容器结束后才能取交付快照 |
| 开发包、保存记录与导出 | `developmentartifact` | 构造、摘要、文本策略、独立 SQLite 组件、配额和精确读取 |
| 既有应用结果资产 | Application Result Artifact | 保持成功 Session / Turn / Run 来源与 64 KiB 正文合同，不保存开发包 |

开发产物复用旧资产的显式保留、不可变内容、精确作用域与独立导出授权原则，不复用旧文本字段、Session 成功条件、结果资产表或生命周期事件。开发 `ArtifactRef` 使用开发包身份和摘要，不伪造 Session / Run 引用，不把 SDK 文件路径作为资源身份。统一结果库展示和跨资产引用接线留给阶段 1；当前没有第二份旧资产内容副本。

## 入口与信任边界

可信宿主把 `Runtime / Session / Identity` 交给 `developmentsandbox.NewDeliverySource`，并以经过本地会话认证的请求调用 `Server.ConnectDevelopmentArtifacts`。这两个 Go 入口不会启动监听器或执行工作，也不会注册公开路由。构造产物服务不启用 SDK、代码执行或生产能力。

`DeliverySource` 在每次取快照时重读同租户、工作区、账户、应用和尝试的持久记录，比较完整委托与计划，并检查沙箱已关闭；失败 / 取消 / 结果未知还必须有持久终止确认，不能只凭控制状态终态保存。原始输入来自已授权三文件快照与可信 Go 测试结果，不接收浏览器 / SDK 上传的正文、来源、退出码或测试报告。`SourceReader` 是可信宿主适配接口，不能接到任意 JSON 上传接口；其返回值仍须经过完整构造校验。

已保存内容不依赖存活执行器、模型、价格配置或暂存目录；读取 / 导出只依赖当前用户资格、精确应用与不可变存储。重启读取不恢复 SDK、模型请求、工具或命令。

## 数据合同与绑定

唯一 schema 为 `contracts/development-artifact.schema.json`，包含四种明确记录：

- `development_artifact.v1`：可审阅开发包；
- `development_artifact_record.v1`：显式保存后的不可变身份、请求和时间；
- `development_artifact_export.v1`：按请求即时生成的导出投影；
- `development_artifact_retention.v1`：沙箱创建前后紧邻落盘、执行前固定的临时保留元数据。

开发包固定绑定：

1. tenant / workspace / account / application、run / task / attempt，以及 binding / authorization revision；账户必须与原委托所有者一致。
2. 完整受限尝试计划、探针计划、计划 schema 版本与规范摘要、应用权威 / 模型 / 定价 / 工具策略摘要；不含凭据或模型上下文正文。
3. `source_kind=frozen_probe_tree`，基准树摘要和三文件清单。当前合成来源没有 Git 提交，不虚构 commit；通用仓库的提交来源合同不在本版本范围内。
4. 每文件相对路径、基准 / 候选文本及各自 SHA-256，候选树摘要，确定性统一 diff 及其摘要。只接受 `go.mod / list.go / list_test.go`，仅 `list.go` 可改变。
5. 每项测试的请求身份、受验候选摘要、固定档案与实际 argv、镜像 / 执行器摘要、起止时间、退出码是否已知、OOM / 截断标志、处理后日志及摘要。
6. 来源创建时间、关闭时固定的快照时间和原始到期时间；未审查、未接受状态固定为 `not_reviewed / not_accepted`。

树摘要沿用计划顺序下 `path + NUL + sha256 + LF` 的 UTF-8 SHA-256。patch 为标准统一 diff 的整文件 hunk，保留末尾换行差异，不执行 Git 来生成或应用包。包摘要为将自身 `digest` 置空后按 Go 明确结构字段顺序生成的紧凑 JSON 的 SHA-256；导出摘要同理，另外绑定保存记录和本次请求 / 导出时间。不是任意重新排版 JSON 文本的摘要。

严格消费者拒绝未知、缺失、重复、大小写别名、null、尾随 JSON 和非法 UTF-8；摘要、字节上限、来源关联、文件顺序、时间与状态关系由 Go 补充核对。schema 的字符串长度不代替 UTF-8 字节限制。非法源码在 JSON 编码前拒绝，避免编码替换字符改变内容。

## 测试事实与部分成果

允许保存已终止的 `completed / failed / cancelled / outcome_unknown` 尝试的完整、可核验候选快照；活动尝试、文件集合不完整、保护文件变化或资源仍未确认结束均拒绝。失败保存不改变尝试状态。

测试状态由规则计算：候选不匹配为 `stale`；退出未知为 `unknown`；截断、OOM、超时、非零退出分别表达；仅已知零退出且无 OOM / 截断才为 `command_passed`。无测试为 `missing`。整体验证投影采用最后一次测试状态，不用更早的通过记录掩盖后来的未知或过期结果。

测试请求、环境与时间必须有效、顺序明确且不晚于快照。沙箱派发 / 清理失败记录未知，不把部分回执视作执行通过。当前包使用沙箱有界观察输出；超过其观察上限仍保留截断事实，不把原始完整日志自动带入包。保存 / 导出不会重跑测试。

`command_passed` 仅表示该命令结果，不表示已修复所有缺陷、全部验收通过或代码安全。独立审查和用户接受尚未实现，不能由 SDK 声明或包内文本改写这些硬状态。

## 显式保存、权限与导出

流程为 `Preview → 审阅实际内容 / 证据状态 / 脱敏结果 → Save(expected digest, request id) → Read / Export`。预览不写资产表。保存重新读取可信来源并重算包摘要；内容、证据或尝试状态发生变化时原确认失效。调用者不能自行上传包作为保存输入。

操作权限为：

| 操作 | 必要权限 |
| --- | --- |
| 预览、精确读取 | `applications:read` + `development_artifacts:read` |
| 保存 | 上述读取权限 + `development_artifacts:save`，应用活跃 |
| 导出 | 上述读取权限 + `development_artifacts:export` |

三项权限登记到既有权限目录，但本轮不改内置角色目录版本，也不自动给既有管理员 / Builder 授权。当前仅可信宿主通过既有身份负责模块显式建立精确授权后使用；正式角色目录与 Web 分配流程在阶段 1 确定。旧 `application_result_artifacts:*`、应用执行权限及任务 bearer 均不代替这三项权限。

适配器每次重读 Web Session、账户、活跃成员关系、权限和精确应用所有者，撤销 Session / 成员 / 权限或禁用账户立即影响后续操作。跨租户、工作区、账户、应用拒绝，不提供管理员跨用户正文读取特例。历史读取不要求原模型 / 定价仍在线。

导出仅为单份精确已保存记录的 JSON 投影，服务端重新校验内容、摘要与敏感策略，并绑定新请求和导出时间；不落第二份内容、不建导出历史、公开链接、分享 token、压缩包或任意路径下载接口。未来 HTTP 必须使用 `Cache-Control: no-store`，当前没有该路由。本轮只在隔离测试目录验证序列化，不进行外部上传或发布。

## 容量与保留

| 对象 | 固定上限 / 策略 |
| --- | --- |
| 单包 | 紧凑 JSON 最多 1 MiB；保存 / 导出包装元数据另有小额固定解析上限 |
| 单源码文件 / 单份日志 | 各最多 64 KiB UTF-8 字节；现有沙箱更严格的 32 KiB 源码 / 8 KiB 观察输出限制不放宽 |
| 文件与测试数量 | 恰好三份文件；测试不超过探针计划工具次数且不超过 8 |
| 工作区内每所有者已保存包 | 跨应用累计最多 64 份、包正文合计 64 MiB；新保存事务内检查 |
| 临时源码 / 测试材料 | 来源创建时固定 24 小时期限；重试和保存失败不续期 |
| 已显式保存包 | 不自动过期；本轮无永久删除、延期或自动淘汰接口 |

容量按实际 JSON 字节计，不按字符或压缩后大小计。额度满明确拒绝新保存，不能覆盖旧包或删除其他应用资产。相同保存请求的幂等重读不再次占用额度。

沙箱创建时写入私有 `artifact-retention.json`，关闭后固定快照时间。`RemoveExpiredArtifacts` 由可信宿主显式调用，只在原期限到达、资源关闭且持久账册与当前会话精确一致时清理自有目录内容，保留资源 / 保留策略元数据；不调用 Docker、不跟随符号链接、不触及原工作树或其他任务。没有后台清理服务。

若宿主已退出，未保存材料不会自动重建成正式开发包。先按既有归属恢复流程核对容器结束，再由获授权的宿主清理其隔离目录；当前自动重建暂存快照和跨进程清理调度未实现。未知资源阻止删除，明确记为保留超期 / 待清理，不能伪称已满足物理删除期限。已保存包仍可重启精确重读。

## 敏感材料规则

只允许授权文本文件、必要结构化来源和有界测试日志；不加入 SDK transcript、完整提示、提供方原始响应、环境、token、隐藏推理、宿主路径或任意额外附件。私有代码本身仍可能敏感，读取和导出始终要求精确授权，扫描通过不等于内容公开。

`text_allowlist_v1` 拒绝常见凭据赋值、Authorization / bearer、私钥头、已知密钥形态、含认证信息的连接地址及宿主私有绝对路径。源码 / patch 命中时拒绝，不能静默删除或改写后继续宣称原候选身份；日志按命中行替换为 `[redacted]`，保留 `log_redacted`，摘要对应实际交付日志。扫描是有界规则，不能保证发现所有语义秘密；用户仍须审阅实际包。

拒绝日志仅使用稳定失败码，不携带内容、底层 SQL、路径或原始错误。包正文不进入公共事件、普通日志、URL、浏览器存储或周志。所有测试数据为合成材料。

## SQLite 与失败恢复

共享 SQLite 增加独立 `development_artifacts` 迁移组件，不新增 DSN、连接池、PostgreSQL 实现或内存回退。旧工作台仍须停服备份后显式 `upgrade`，`serve` 不自动升级；本轮不操作用户运行库。

包正文、保存请求、身份、摘要和字节数在同一 `BEGIN IMMEDIATE` 事务插入；数据库触发器补充配额与禁止更新 / 删除约束。保存请求唯一键包含 tenant / workspace / account / application。相同请求和包摘要返回同一记录；同请求不同摘要返回冲突。

- 确认过期或候选变化：拒绝保存，重新预览后确认，不替用户选择旧包。
- 存储失败：不改变尝试、不回退内存、不重跑执行；来源在原期限内仍可重试。
- 提交成功但回执丢失：先按当前权限查原请求，重返原记录；即使临时来源已过期也不重新读取或执行来源。
- 数据损坏：精确读取核对记录摘要、列 / JSON 作用域、包字节数、所有内容摘要及合同；错误则拒绝返回，不以空内容或最新其他记录代替。
- 导出失败：保留原包，可重新授权后重试即时投影，不修改保存记录。
- 重启：只读已保存内容；不会自动补保存、重放命令、恢复 SDK 或触发物理清理。

稳定失败码前缀为 `development_artifact_`，后缀为 `invalid / denied / sensitive / source_expired / conflict / quota_exceeded / store_unavailable / corrupt / not_found`。来源不可用不得透传原始底层错误。
