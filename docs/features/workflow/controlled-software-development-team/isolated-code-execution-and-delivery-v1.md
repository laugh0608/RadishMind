# 受控开发团队：隔离代码执行与候选交付 v1

更新时间：2026-10-31

状态：固定三文件 Go 探针的代码容器、受限文件 / 固定测试工具及归属清理已实现并完成真实容器验收；SDK 收尾接线已定向验证。固定探针候选包合同与内部 SQLite 保存 / 导出已实现并定向验证；真实 SDK 同次修改 / 测试 / 保存 / 导出及命令中取消已固定响应联合验收；通用仓库准入与正式 Web 交付尚未完成。

所属功能：[多 Agent 协同与受控软件开发团队](../controlled-software-development-team-v1.md)。本页覆盖代码副本和实际工具影响，团队资格见[运行状态专题](team-runtime-state-and-artifacts-v1.md)。

## 信任边界与目标

工作台容器已通过的启动、权限及数据恢复验收，只证明工作台交付。执行任意仓库的构建 / 测试会运行该仓库代码，必须新增独立隔离边界；工作副本或 Git worktree 本身不提供安全沙箱。

首版采用独立、受限的代码执行容器与固定仓库副本。可信 Go / Python 执行控制层负责 SDK、委托、授权、事件和工具派发；不可信代码容器只承载授权代码与命令。若 SDK 默认文件 / 终端工具不能通过控制层访问容器，该集成方式不通过选型验证，不能改为在宿主机直接执行。

容器隔离也不是生产多租户安全结论。首版面向本机内部开发者、明确授权的任务和副本；恶意代码、逃逸防护及共享环境要有独立验证，未完成前不得公开为通用代码执行服务。

## 仓库准入与副本

1. 用户显式选择允许访问的仓库及基准提交，平台核对来源、作用域、访问权限和任务路径；不按模型生成的本机路径寻找或授权仓库。
2. 记录精确 Git 提交和干净来源状态。首版只接受确定的已提交基准，未提交用户修改不被覆盖或自动打包；需要纳入时由用户另行确定输入快照。
3. 只导入允许的文件集合；排除平台数据、凭据、忽略的私有配置及未授权子模块 / 外部目录。拒绝路径逃逸、特殊设备文件和不受控符号链接。
4. 每个写入角色和每次尝试建立独立副本，集成另用新副本。来源仓库保持只读，不把用户原工作树作为 Agent 编辑目标。
5. 记录副本身份、所有者、基准、目录和清理策略。依赖缓存来源和可写性明确，跨任务不共用可写缓存作为可信输入。

本仓库普通人工 / AI 协作仍遵循直接在 `dev` 工作的约定；产品未来创建的隔离任务副本不改变这一仓库协作规则，也不授权本次文档任务创建 worktree。

受限 SDK 工作进程已通过真实 Agent 固定响应往返、等待取消和父存活管道失联退出验证，Go 负责独立进程组与有界清理；该证据覆盖可信 SDK 层；本轮另取得固定 Go 代码容器的文件隔离与归属终止证据，不将两轮分层试验当作联合证据。随后另行完成[同次任务联合技术验收](../../../devlogs/2026-W44.parts/development-joint-20261031.md)，三条用例分别保留正常、过期和未知测试事实。

当前 `tool-calls` 在持久消费、预算预留和事件同事务提交后只返回 `202 queued`；可信 Go 的 `DispatchTool / CompleteTool` 钩子现可显式接到 `WorkerLaunch.Sandbox`，校验绑定后调用私有候选文件工具及固定容器验证。SDK 不能提交完成回执。完整参数、只读快照、容器配置、归属账册与证据边界见[沙箱合同](../../../contracts/development-code-sandbox-v1.md)。

## 执行环境约束

| 项目 | 首版拟定约束 | 必须取得的证据 |
| --- | --- | --- |
| 镜像与身份 | 固定镜像摘要、非 root、根文件系统只读、移除多余 capability | 实际目标平台启动与权限验证；不能用工作台镜像结果代替 |
| 文件系统 | 仅代码副本、受限临时目录和有界产物区域可写 | 越界、符号链接 / 硬链接逃逸、特殊文件、磁盘超额拒绝 |
| 宿主资源 | 不挂载 Docker socket、平台数据库、用户秘密目录、原工作树 | 挂载清单及容器内读取失败证据 |
| 网络 | 默认无外网；模型访问由可信控制层完成 | 代码进程不能直连提供方、平台管理接口或任意外部地址 |
| 凭据 | 代码进程不继承 Gateway / Provider / 平台凭据和宿主环境 | 环境与文件扫描；模型请求由受限委托负责 |
| 资源 | 有界 CPU、内存、进程数、磁盘、输出和时间 | 资源超限真实终止及可定位失败，不伪造测试通过 |
| 生命周期 | 所有容器 / 进程标注所属运行与尝试 | 取消、超时、崩溃后核对及按归属清理 |

Docker 管理权限只能存在于可信执行控制层，代码容器不得取得该通道。联合试验中 Go 控制程序拥有管理通道，SDK 降至 `65532:65532` 并清空有效 / 许可 capability；管理 socket 与控制数据分别由容器内 Linux 私有目录遮蔽，实测 SDK 打开数据库及连接 socket 均被拒绝。宿主共享文件系统的 `0700` 模式位曾未阻止读取，不能仅凭显示权限声明隔离。执行环境的网络隔离不能阻断控制层的审计与取消；需要验证两条通道各自的失败行为。

依赖预装在受审镜像或只读可校验材料中。默认禁止任务自行联网安装依赖、修改锁文件或拉取新镜像；若任务确需这些变化，形成新的可审阅授权修订，不能从仓库脚本、README 或 Agent 消息推定用户同意。

角色可写源码路径必须同时由容器挂载 / 文件系统权限和候选导出校验约束，其余源码只读；构建缓存与输出使用单独的受限可写区域。不能只在文件工具中检查路径，却让测试脚本写入其他角色文件。验证后核对完整差异，出现未授权源码修改时拒绝该候选并保留证据；具体挂载组合须在阶段 0 真实验证。

当前落地范围是已冻结的三文件 Go 探针：每次验证使用独立无网络容器、两份只读挂载、1 GiB / 2 CPU / 128 进程及 512 MiB 临时区，可信 PID 1 最多 120 秒硬期限。实际基准预期失败、修正候选 8 项通过，且验证源码只读、秘密不继承、网络拒绝、磁盘 / 进程上限、取消、硬期限、遗留容器清理与输出超限。一般仓库导入、生产恶意代码防护和其他平台不能据此视为通过。

## 首版工具集合

参数与工具身份使用[尝试控制合同](../../../contracts/development-attempt-control-v1.md)中的 `development-tool-action / development-tool-call`。SDK 元数据分离、规范路径语法、可信提议 / 预留摘要比较已离线实现；路径授权、提议原子消费及固定探针的私有文件 / 只读测试挂载已实现；仅 `list.go` 可经 Go 工具原子替换，测试期间全部源码只读。候选包构造、显式保存和导出已接到独立开发产物负责模块；通用仓库及新增验证档案仍待实现。

| 工具 | 输入与输出 | 限制 |
| --- | --- | --- |
| 文件读取 / 检索 | 副本相对路径、范围 / 查询，返回有界片段与文件身份 | 不能访问其他任务、秘密路径或平台文件 |
| 应用 patch | 精确基准摘要、修改路径、内容或 patch，返回实际变更摘要 | 逐次验证路径、类型、预期版本及角色所有权，拒绝越界 |
| 执行验证档案 | 已审阅档案引用和受限参数，返回命令、环境、退出码及日志引用 | 不接任意宿主 shell；档案仍在隔离容器内运行仓库代码 |
| 读取产物 / diff | 精确任务产物引用，返回校验过的摘要和有界内容 | 不允许以任意绝对路径作为下载接口 |

命令档案不能只按字符串前缀判定安全；参数、工作目录、环境、脚本内容和网络影响共同受限。即使是 `npm test` 或 `go test`，也按不可信代码执行处理，命令允许列表不能替代容器隔离。

只读审查者 R 的工具只能读取候选与证据。B、C、D 的写路径分别列入计划；共享 schema / 类型有单一负责人。工具授权失败保留明确事件，不换一个工具、路径或模型绕过。

## 集成与测试证据

各角色只输出自己副本中的候选 patch；可信集成步骤验证来源和摘要，再应用到基于同一提交的新集成副本。冲突交回协调者 / 用户决定，不用自动选择一方或直接改写原仓库兜底。

测试与审查都针对集成副本的精确摘要。测试角色按需求准备验收，不信任开发角色声称的执行结果。每条验证记录实际命令、档案版本、环境 / 依赖摘要、起止时间、退出码、受验代码与日志；运行不完整、输出截断或环境缺失单列，不能解释为通过。

修改测试、降低断言、跳过用例或变更公共契约必须可见并接受审查；不能以“为了通过检查”为由扩大任务范围。返修产生新候选，旧测试和审查证据在受影响范围内失效。

## 候选交付包

交付 manifest 绑定需求 / 计划 / 团队版本、源提交、候选摘要、完整文件清单、patch 摘要、验证与审查引用、模型 / 工具策略和未验证项。导出前再次检查路径、文件类型、体积与敏感材料；可追溯身份不能使用容器绝对路径代替。

首版优先交付受限文本 patch 和结构化报告；二进制修改、子模块、外部符号链接、大文件和 Git hooks 不默认接受。正式[开发产物合同](../../../contracts/development-artifact-v1.md)现已固定 JSON 包、独立权限、摘要、配额、临时保留及恢复规则，并实现独立 SQLite 负责模块；不扩展旧结果正文、不提供压缩包、公开下载 API 或正式 Web。

用户显式保存和导出候选不等于授权合入。应用到用户原仓库、创建提交、推送、合并及发布留在首版范围外；未来如加入，必须绑定被接受的精确候选和目标基准，另行设计权限及冲突行为。

## 失败与清理

- 在命令启动前持久化派发身份；回执丢失、取消超时或进程失联时保留结果未知，不因缺少输出就重跑命令。
- 超时与取消停止新增动作，并结束所属容器和进程树；保留失败原因及可审阅的部分成果，不能只结束 SDK 协程。
- 收尾核对容器、进程、网络与临时资源，只清理由本次运行拥有的对象；不执行全局 Docker prune，不删除用户原库或其他任务。
- 临时副本与日志按预先确定的期限清理，用户保存的候选包按显式结果生命周期处理；保存失败不能先删唯一可核验产物。

阶段 1 必须用真实隔离代码任务验证正常修改与测试，同时覆盖越界、秘密读取、网络拒绝、资源超限、取消、冲突、产物失败和停止清理。固定响应可替代模型输出驱动工具链；不得把该结果称为自主编码效果。
