# 受控开发团队：框架选型与 Gateway 接入 v1

更新时间：2026-10-31

状态：离线探针合同与代表任务已实现；SDK 试验输入固定为 `openhands-sdk==1.59.0`，未安装运行、未形成完整依赖锁或采用结论。

所属功能：[多 Agent 协同与受控软件开发团队](../controlled-software-development-team-v1.md)。本页只负责执行框架、模型协议和采用证据；团队权威状态见[运行状态专题](team-runtime-state-and-artifacts-v1.md)，工具影响边界见[隔离执行专题](isolated-code-execution-and-delivery-v1.md)。

## 选型结论与依据

优先验证 OpenHands Software Agent SDK 作为单角色编码执行层。Go 保有有限团队流程、授权、预算和状态，不将这些职责转交 SDK，也不新建通用工作流引擎。

2026-10-31 核对的[官方 SDK 说明](https://docs.openhands.dev/sdk)介绍了面向软件开发的 Python / REST 接口；[自定义工具说明](https://docs.openhands.dev/sdk/guides/custom-tools)提供工具动作、观察值和执行器的扩展方式。这些是候选依据，不证明其默认工具已满足本项目隔离策略。

[SDK 项目声明](https://github.com/OpenHands/software-agent-sdk/blob/main/openhands-sdk/pyproject.toml)当次记录 Python `>=3.12`，包含 LiteLLM 等额外依赖；仓库当前 `requirements-dev.txt` 仅声明 `jsonschema>=4.0`，工作台镜像使用 Python 3.12。因此版本下限有交集，但实际依赖解析、体积、平台支持和许可证仍待核验，不能直接写入已验收的工作台运行环境。上游 `main` 是观察来源，不是采用版本锁。

| 候选 | 本项目中的位置 | 决策 |
| --- | --- | --- |
| [OpenHands SDK](https://github.com/OpenHands/software-agent-sdk) | 单角色编码执行、受控工具适配 | 首选验证；满足下表关键条件后才锁定版本 |
| [LangGraph](https://github.com/langchain-ai/langgraph) | 后续复杂编排候选 | 首版不引入，避免重复状态和恢复权威 |
| [Microsoft Agent Framework](https://github.com/microsoft/agent-framework) | 编排替代候选 | 首选方案不能满足关键条件时，使用同一任务另作比较 |
| [CrewAI](https://github.com/crewAIInc/crewAI)、[MetaGPT](https://github.com/FoundationAgents/MetaGPT) | 角色和协作流程参考 | 不移植完整框架，不并存多套执行与调度机制 |

表中职责安排是本项目的选型判断，不是这些框架的兼容性测试结论。首选不满足条件时停止采用并记录原因，不在运行中自动切换框架或直接绕过 Gateway。

## 本仓库的实际接入缺口

| 当前来源 | 已有事实 | 对本功能的影响 |
| --- | --- | --- |
| `contracts/agent-copilot-profile-draft.schema.json` | `tool_hints_policy.allow_tool_calls` 固定为 `false`，任务限定既有 Radish / RadishFlow 建议场景 | 旧建议型 Agent 不能直接作为编码执行档案，也不能塞入任意角色提示和模型配置 |
| `services/platform/internal/httpapi/agent_copilot_invocation.go` | 最大调用时限为 30 秒 | 长任务需要独立生命周期，不能简单扩大旧调用上限 |
| `services/platform/internal/httpapi/northbound.go` | 既有桥接请求设置 `allow_tool_calls=false` | OpenAI-compatible 名称不证明 SDK 工具调用语义可用 |
| `services/platform/internal/bridge/worker_pool.go` | 已有受控短请求工作进程池 | 可参考取消 / 关闭原则，不长期占用该池运行开发任务 |
| Gateway、API key、模型目录、请求历史 | 已有开发测试态作用域和调用归因 | 复用现有负责模块；新增委托与预算语义仍需设计 |

详细设计必须明确工具描述、工具调用标识、参数校验、工具观察值、结构化输出、结束原因、用量、错误与取消的完整往返。不能把工具调用 JSON 嵌入普通答案正文再猜测解析，也不能用 Copilot 响应修复器制造执行成功。

## 拟定模型调用通道

1. Go 冻结团队 / 角色版本、模型引用和显式活跃应用绑定，校验当前账户、工作区与执行资格。
2. 可信执行控制层持有任务级最小权限委托；SDK 通过受限通道请求模型，不接收原始提供方密钥，也不把平台主凭据传给代码容器。
3. Gateway 验证应用、角色调用来源、模型能力和预算预留，选择已确定的提供方；每个实际尝试产生可归因记录。
4. 模型返回的工具请求交给平台工具授权与隔离执行路径，工具观察值经大小、类型和敏感信息处理后返回该角色上下文。
5. 完成、超时、取消或失败统一映射为结构化事件；SDK 原始异常、请求头、完整上下文和密钥不进入公开事件或日志。

首版优先验证非流式往返，流式只在需求与 SDK 采用条件明确后加入。详细设计须决定复用兼容端点的版本化扩展还是独立内部端点；本页不分配公开路由、scope 名称或 schema 版本。旧端点、旧 Agent 建议协议和既有客户端继续按原合同拒绝不支持的工具请求。

任务级委托的签发、到期、撤销和活跃应用归因是阶段 0 必须解决的决策。不能把浏览器 Session 当作模型 API key，也不能给多个角色复制一个无边界长效密钥。执行资格与预算由 Go 重新验证，SDK 的“允许”选项不承担平台授权。

## 采用前必须取得的证据

以下试验需要明确依赖、镜像、隔离目录和服务范围；真实模型仍暂停。当前已实现独立离线探针，实际 SDK / Gateway 兼容试验尚未执行。

每次试验在下载前固定候选版本及依赖锁输入，记录实际解析结果与镜像摘要；验证通过后再形成正式采用锁，不以浮动 `latest` 作为可复验依据。

| 关键条件 | 试验方法 | 拒绝采用的情形 |
| --- | --- | --- |
| Gateway 往返 | 固定响应驱动工具请求 → 合法工具观察 → 下一模型响应，核对调用标识与模式 | 必须直连提供方、丢失工具身份或无法区分结束 / 失败 |
| 工具可限制 | 仅注册经控制层验证的文件 / 检索 / patch / 命令档案工具，拒绝默认无限制终端 | SDK 可绕过工具入口执行宿主机命令或递归委派 |
| 事件可导出 | 观察模型、工具、重试、压缩、结束等事件，并验证序号映射与脱敏 | 存在不可识别的调用或无法可靠归因 |
| 取消可收敛 | 在模型等待和命令执行时分别取消，确认进程树、容器和预算处理 | 只停界面或协程，实际命令仍运行 |
| 预算可约束 | 并发调用前预留，处理缺失用量、超时未决和费用估算 | 隐式模型调用、重试或压缩绕过预算 |
| 运行环境可交付 | 在独立执行镜像中解析锁定依赖、核对许可证、平台与镜像摘要 | 要求污染平台环境、扩大宿主权限或无法复现构建 |
| 状态可分工 | SDK 重启 / 崩溃事件交回 Go；默认关闭自动命令重放 | SDK 自行恢复写入并覆盖平台的中断判断 |

任何上下文压缩、重试、回退或 SDK 内部模型调用，都计入同一角色尝试与总预算。默认关闭框架自动重试、递归派生团队和动态工具加载；无法关闭的行为必须能被控制和计量，否则不采用。

## 依赖、代码组织与兼容原则

- 编码 SDK 使用独立 Python 执行环境及依赖锁，作为待实现模块维护；不把全部依赖塞进现有短请求 runtime，也不提前引入多框架抽象层。
- Go 新增职责明确的团队领域和执行协调边界，复用身份、Gateway 和存储基础；不把团队对象全部放入通用 `manager`，也不以全量拆分 `httpapi` 为前置。
- Python 适配只在确有两侧合同转换时建立；不做空转 wrapper，不让第三方对象直接成为跨语言或数据库合同。
- canonical schema 与严格消费规则随实际合同实施。当前仅新增探针计划 / 工具请求 schema 及 Go 校验器，不含正式团队协议、迁移或 HTTP API；UI 尚无消费者，不提前生成 TypeScript 类型。
- 首版错误至少区分：协议不支持、模型资格不符、工具拒绝、预算不足、SDK 不可用、模型超时、取消未确认、产物失败和状态未知。稳定错误码在正式合同中确定。

## 首个探针的落实情况

代表任务与三文件基准已固定，见[合成任务说明](../../../../scripts/eval/fixtures/development-task/README.md)。Go CLI 仅校验计划、创建新私有副本并检查候选；计划 / 工具请求合同拒绝任意命令、路径扩权与不明确字段。人工修正的先失败后通过复验证明任务可用，不证明 SDK 接入。

SDK 试验候选来自 [PyPI 1.59.0](https://pypi.org/project/openhands-sdk/1.59.0/) 与[上游 v1.59.0](https://github.com/OpenHands/software-agent-sdk/releases/tag/v1.59.0)，固定版本输入和独立镜像配方已准备。解析报告、wheel 哈希锁、实际安装报告与镜像摘要须在获准运行后保存；配方尚未构建，不能声明完整依赖可复现、许可证合格或平台兼容。命令、限制和清理方式见[SDK 候选说明](../../../../scripts/eval/development_probe/README.md)。

探针工具解析不承担实际顺序、重放、摘要一致性或累计预算控制；这些与真实 SDK 工具往返、事件及取消一起继续实施。采用结论仍按本页关键条件判断，不因版本输入已固定而提前通过。范围与证据集中记录在[任务卡](../../../task-cards/development-task-probe-v1-plan.md)。
