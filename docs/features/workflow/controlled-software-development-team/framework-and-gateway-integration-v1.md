## 选型结论与依据

优先验证 OpenHands Software Agent SDK 作为单角色编码执行层。Go 保有有限团队流程、授权、预算和状态，不将这些职责转交 SDK，也不新建通用工作流引擎。

2026-10-31 核对的[官方 SDK 说明](https://docs.openhands.dev/sdk)介绍了面向软件开发的 Python / REST 接口；[自定义工具说明](https://docs.openhands.dev/sdk/guides/custom-tools)提供工具动作、观察值和执行器的扩展方式。这些是候选依据，不证明其默认工具已满足本项目隔离策略。

[SDK 项目声明](https://github.com/OpenHands/software-agent-sdk/blob/main/openhands-sdk/pyproject.toml)当次记录 Python `>=3.12`，包含 LiteLLM 等额外依赖；仓库当前 `requirements-dev.txt` 仅声明 `jsonschema>=4.0`，工作台镜像使用 Python 3.12。因此版本下限有交集，但实际依赖解析、体积、平台支持和许可证仍待核验，不能直接写入已验收的工作台运行环境。上游 `main` 是观察来源，不是采用版本锁。

| 候选 | 本项目中的位置 | 决策 |
| --- | --- | --- |
| [OpenHands SDK](https://github.com/OpenHands/software-agent-sdk) | 单角色编码执行、受控工具适配 | 首选候选；试验版本与依赖已锁定，满足下表关键条件后才正式采用 |

## 拟定模型调用通道

1. Go 冻结团队 / 角色版本、模型引用和显式活跃应用绑定，校验当前账户、工作区与执行资格。
2. 可信执行控制层持有任务级最小权限委托；SDK 通过受限通道请求模型，不接收原始提供方密钥，也不把平台主凭据传给代码容器。
3. Gateway 验证应用、角色调用来源、模型能力和预算预留，选择已确定的提供方；每个实际尝试产生可归因记录。
4. 模型返回的工具请求交给平台工具授权与隔离执行路径，工具观察值经大小、类型和敏感信息处理后返回该角色上下文。
5. 完成、超时、取消或失败统一映射为结构化事件；SDK 原始异常、请求头、完整上下文和密钥不进入公开事件或日志。

首版优先验证非流式往返，流式只在需求与 SDK 采用条件明确后加入。已选择独立内部监听器，入口、任务委托 audience、受限原生模型字段与工具参数见[尝试控制合同](../../../contracts/development-attempt-control-v1.md)。已提供显式可信 Go 接线及独立回环监听器；默认平台 / 工作台不启动，不注册公开路由或新增 scope 权限。原生后端已增加单一非流式 HTTP 实现，并通过实际固定上游验证，不转发旧建议桥接，也不合成工具执行成功。旧 Agent 建议协议与既有客户端保持。实测现有 Chat Completions 会忽略未知工具字段，仍返回建议文本，不是工具兼容入口；正式接入必须明确版本化通道及不支持请求的拒绝策略，不能把 HTTP 200 当成 SDK 工具接入成功。

任务级委托已冻结为单尝试、不透明短期 bearer 与无秘密描述分离，绑定活跃应用 / 权限修订 / 模型和策略摘要；到期 / 撤销规则已离线验证，可信 Go 签发已连接当前本地 Session、管理员、应用、模型和定价负责模块；确认精确计划后只向可信宿主一次交接凭据。凭据交接已在独立镜像的真实 SDK 工作进程中验证，不进入 argv、环境或公开事件。不能把浏览器 Session 当作模型 API key，也不能给多个角色复制一个无边界长效密钥。执行资格与预算由 Go 重新验证，SDK 的“允许”选项不承担平台授权。

每次试验在下载前固定候选版本及依赖锁输入，记录实际解析结果与镜像摘要；验证通过后再形成正式采用锁，不以浮动 `latest` 作为可复验依据。

| 关键条件 | 试验方法 | 拒绝采用的情形 |
| --- | --- | --- |
| Gateway 往返 | 固定响应驱动工具请求 → 合法工具观察 → 下一模型响应，核对调用标识与模式 | 必须直连提供方、丢失工具身份或无法区分结束 / 失败 |
| 工具可限制 | 仅注册经控制层验证的文件 / 检索 / patch / 命令档案工具，拒绝默认无限制终端 | SDK 可绕过工具入口执行宿主机命令或递归委派 |
| 事件可导出 | 观察模型、工具、重试、压缩、结束等事件，并验证序号映射与脱敏 | 存在不可识别的调用或无法可靠归因 |

| 预算可约束 | 并发调用前预留，处理缺失用量、超时未决和费用估算 | 隐式模型调用、重试或压缩绕过预算 |

任何上下文压缩、重试、回退或 SDK 内部模型调用，都计入同一角色尝试与总预算。默认关闭框架自动重试、递归派生团队和动态工具加载；无法关闭的行为必须能被控制和计量，否则不采用。

## 依赖、代码组织与兼容原则

- 编码 SDK 使用独立 Python 执行环境及依赖锁，已有受限 SDK 工作进程与固定 Go 代码执行器，分层固定响应证据不代替联合任务验收与正式采用；不把全部依赖塞进现有短请求 runtime，也不提前引入多框架抽象层。
- Go 新增职责明确的团队领域和执行协调边界，复用身份、Gateway 和存储基础；不把团队对象全部放入通用 `manager`，也不以全量拆分 `httpapi` 为前置。
- Python 适配只在确有两侧合同转换时建立；不做空转 wrapper，不让第三方对象直接成为跨语言或数据库合同。
- canonical schema 与严格消费规则随实际合同实施。当前除探针外已新增单尝试控制与工具调用 canonical schema、严格 Go 消费及内存领域规则，不含完整团队资源协议、迁移或 HTTP API；UI 尚无消费者，不提前生成 TypeScript 类型。
- 首版错误至少区分：协议不支持、模型资格不符、工具拒绝、预算不足、SDK 不可用、模型超时、取消未确认、产物失败和状态未知。稳定错误码在正式合同中确定。

### 2026-10-31 兼容检查结论

- 非流式 `LLM.completion` 使用唯一自定义工具，未附加 executor；固定工具调用 → 观察值 → 最终响应实际发出两次请求，工具名 / 标识和结束原因一致。不是完整 Agent、文件修改或命令执行验收。
- 显式 `num_retries=0`、不配置 fallback 时，400 / 429 / 500 与模型等待超时均只产生一次 HTTP 请求。HTTP 错误由 SDK 异常包装，平台不能只读外层 `status_code`；原始异常也不能直接公开。
- 规范消费者拒绝畸形 / 重复字段、跨探针、越界路径、超预算序号、任意命令与未知工具；SDK 返回内容本身不授予执行权限。普通文本成功响应不能通过工具试验。 SDK 自动声明的可选 `summary` 也不是 canonical 授权字段，已作为负例拒绝；本轮已实现显式分离的离线规则，后续需接入真实适配器，不能放宽授权 schema。
- SDK 默认重试为 5；`LocalConversation.pause()` 的当前实现只在步骤之间生效，正在等待的模型调用结束后才暂停。此项为安装代码核对，尚非实际 Agent 取消验收；必须由 Go / 执行进程控制层实现中断和终止期限。
- 上游不返回 usage 时，当前 SDK 依赖链的响应对象会填入零 token。正式预算 / 用量由 Gateway 保有独立权威，缺失用量必须记录未知或有标记估算，不能直接采纳 SDK 零值。
- 捕获的两个合成请求经 Go 内存 handler / fake bridge 复验后，旧 Gateway 返回 HTTP 200 / `stop`，保留 `allow_tool_calls=false`，不传递工具标识。这证明旧入口不兼容，不是正式 Gateway 接入成功。

## 2026-10-31 采用复评结论

**保留首选候选，暂不正式采用，阶段 0 不退出。** 联合固定响应证据支持受控适配的技术可行性，但不能覆盖以下未决项。下表为原基线复评快照；后续变体结果见下节。复评证据与精确版本见[本次记录](../../../devlogs/2026-W44.parts/development-adoption-20261031.md)。

| 条件 | 复评结果 | 关闭条件 |
| --- | --- | --- |
| SDK / 工具 / 事件 / 取消 / 预算 / 产物 | 固定 Go 任务已取得分层及联合技术证据 | 保留现有通过范围；依赖或适配发生变化时重验受影响路径 |
| 锁与许可证 | 138 个锁定分发包已有元数据；必需链 `openhands-sdk==1.59.0 → lmnr==0.7.67 → lmnr-claude-code-proxy==0.2.0` 包含 `LicenseRef-Proprietary` | 明确内部使用和拟分发镜像的许可依据，或经批准调整依赖方案并重新锁定 / 验收；关闭遥测不移除必需依赖 |
| 提供方原生传输 | `NativeBackend` 仅有测试实现；当前资格检查不证明工具协议兼容 | 实现明确提供方档案的真实 HTTP 传输，并以固定上游验证完整工具往返及失败 / 取消；真实厂商接入资格另验 |
| 阶段 1 产品范围 | 已有完整目标，尚缺公共操作合同、生命周期接线及视觉依据 | 确认单 Agent 固定 Go 交付边界、正式权限 / API、启动和重启行为以及 A 级设计依据 |

许可证核验必须区分包元数据、精确发行物正文和最终镜像分发义务。`agent-client-protocol==0.12.1` 的 wheel 含 Apache-2.0 正文；SDK wheel 没有许可证文件，上游 `v1.59.0` 为 MIT，不能据上游标签假称镜像内已包含告知。当前冻结候选的 `certifi`、`tqdm` 及 hf-xet 下的 `colored` / `option-ext` 含 MPL 声明（当前 119 个 wheel 不含 `orjson`），另有复合或笼统许可证声明需要逐项确认。此轮不是全部 wheel、原生捆绑库、基础镜像或 Docker CLI 的许可闭合。代理包[官方元数据](https://pypi.org/project/lmnr-claude-code-proxy/0.2.0/)和 wheel 正文指向[服务条款](https://laminar.sh/policies/terms)；专有声明本身不等于禁止采用；未决点是内部使用及拟交付方式的授权依据，现有证据不足以批准随本项目镜像再分发。不得以 `--no-deps` 删除必需包或静默降版制造合规结论。

### 原生 HTTP 传输档案与验证（2026-11-05）

项目所有者已确认按计划实施；Go `NativeBackend` 首版限定一个冻结的 OpenAI-compatible 非流式档案，已完成本机固定上游验证；仍经平台受权通道访问，不让 SDK 持有提供方密钥。按当前配置和凭据负责模块解析 endpoint / 模型 / 密钥，派发前重查修订与资格。原生传输属于既有开发通道的缺失实现，不改变旧建议型 Gateway 的工具关闭语义。

- 请求 / 响应严格消费工具定义、调用标识、工具观察、结束原因和用量；缺失用量保留未知，拒绝不支持模式、畸形 / 超限响应和工具身份错绑。
- 显式控制总期限、取消、响应体上限、TLS、端点范围、代理和重定向；禁止自动重试 / 回退，凭据不随重定向流出。受控回环固定上游只用于验收，不成为任意外连例外。
- 错误只输出结构化类别与安全摘要，保留请求归因、预留 / 回执和取消后未决用量；不公开原始提供方响应或密钥。
- 验证必须实际穿过 HTTP 适配和当前配置 / 凭据接线，覆盖两次工具往返、401 / 429 / 5xx、超时 / 取消、缺失 usage、非法 JSON、超限与禁止重定向。现有接口内固定函数不能替代该证据。

固定上游可以证明真实传输实现的技术行为，不能证明某个厂商 / 模型支持工具、真实计量或开发质量。真实模型继续暂停；恢复后按精确提供方 / 模型另验并记录资格，不先开启该模型的正式执行能力。公共 Web 入口、生命周期与 UI 的纵向交付属于阶段 1；阶段 0 先确认它们的合同与范围，不提前编码。

本轮实现与限制见[尝试控制合同](../../../contracts/development-attempt-control-v1.md#原生-http-档案)。三次模型 HTTP 请求完成两轮工具提议 / 观察值往返，覆盖当前配置 / 凭据接线与资格撤销；401 / 429 / 5xx、超时 / 取消、缺失用量、非法 JSON、超限和禁止重定向已定向验证。工具执行仍用合成观察值，本轮不重复声称真实 SDK / 代码容器联合验收。真实提供方的工具资格、输入 token 上界与费用继续待验。
