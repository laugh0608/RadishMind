## 阶段 1：单 Agent 隔离开发交付

目标是用户在正式 Web 对一个任务发起、取消、审阅并显式保存候选 patch 与测试证据，建立后续团队比较基线。

首版按[公开交付合同](../../../contracts/development-task-delivery-v1.md)限定固定三文件 Go 树、只改 list.go、受保护的预置测试、单模型串行工具与一次尝试。只审阅、显式保存、JSON 导出和精确重读，不接受任意 Git 来源、shell、依赖安装或自动合入。

同一交付范围包含 Go 运行 / 授权、Python 执行器、受限代码容器、Gateway、文件 / 验证工具、产物和正式 Web。沿 canonical schema / 权限 → SQLite 事务与协调 → 严格 HTTP → Web → 实际隔离与浏览器验收连续实现，普通步骤不重复审批。通用仓库、团队 / 群聊返修、额外存储 / 平台及完整路由解释 / 回放后置；只提供合同必需且有权威来源的信息。

完成依据：

- 一份固定基准代码经过实际编辑和构建 / 测试，产物与证据绑定同一候选。
- 启动 / 取消权限、模型 / 工具预算、目录和网络边界真实生效。
- 超时、子进程、越界、模型失败、存储失败和结果未知均如实表现。
- 页面刷新与服务重启只恢复记录，不重放模型或命令；显式保存的交付包可精确重读。
- 技术验收使用固定响应时明确标记，不能宣称 Agent 自主完成软件开发或任务效果达标。

初始持久化选择内存测试与工作台所需 SQLite；是否扩展 PostgreSQL 以明确交付需要决定，不为形式上的三种存储同时扩工作量。

### 阶段 1 后：真实单 Agent 价值复核与投入决定

2026-11-10 所有者确认：先完成单 Agent 技术交付，再取得小范围真实单 Agent 价值依据，然后决定是否建设固定团队。此处是阶段 1 与 2 之间的选择点，不重编阶段编号，不要求提前建设阶段 4 的完整比较装置。

- 必要阻塞：真实模型仍暂停；恢复前明确提供方工具资格、完整输入计量、费用 / 时间上限、有限任务集、许可 / 数据与独立验收。固定响应和人工预置修复结果不能作为价值证据。
- 任务尽量复用已支持的 Go 来源 / 路径 / 命令边界；原三文件单题只能提供窄域初步观察。需要变体或新来源时先确认最小范围，不直接升级为通用仓库或十二题全矩阵。
- 记录每次需求、基准、真实候选 / 测试、完成质量、错误完成声明、人工澄清 / 干预 / 返工、失败和耗时 / 费用；独立核对实际结果，保留未知量和失败，结论注明样本限制。
- 结束必须作出继续团队、先修正单 Agent 或暂缓的决定，并说明具体阻塞与预期收益。没有结果或窗口不恢复就等待，不以增加团队、模型裁判或评测平台填补等待期。

工作台独立用户试用仍按原交付专题开放跟踪，不因本选择点自动恢复或变成已完成。阶段 1 技术完成、真实任务价值和后续团队比较分别报告。

## 阶段 2：固定开发团队

在单 Agent 技术交付和上述价值复核支持继续投入、所有者确认团队范围后，接入 A/B/C/D/R。A 的计划与接口先明确，再允许 B / C 在独立副本有限并行，D 提前准备验收并在集成版本测试，R 在独立上下文审查同一候选，问题进入有上限的定向返修。

完成依据为一个前后端联动代表任务的完整候选交付，覆盖共享契约负责人、依赖拒绝、集成冲突、测试变化 / 过期、独立审查、返修超限与预算耗尽。不能只展示五个角色聊天或分别返回片段。

角色定义和模型映射使用精确版本；团队阶段不默认开放动态组队、递归委派、任意工具、自动合入或新的业务写回。代码容器写授权不能映射成 Action Safety 的 `write_allowed_by_policy`。

## 阶段 3：持续协作与中断处理

在已有基本历史 / 取消 / 保留能力上，完善群聊定向反馈、计划修订、运行间对照、清理、诊断和用户显式创建后续尝试。重读历史与继续执行是不同动作，不能用框架检查点隐式恢复副作用。

完成依据包括长期记录可读取、权限撤销后内容与动作受控、临时材料按期清理、已保存产物保留明确、崩溃后的存活容器和部分产物可核对。未知执行不会被伪装为成功，后续尝试不重复旧影响。

## 阶段 4：真实任务效果验证

本阶段保留完整单 Agent / 团队比较；首次单 Agent 价值复核已前移到阶段 1 后，不等待本阶段才判断基础价值。团队能力成立并恢复获准模型窗口后，用相同基准、任务、验收和预算上限比较单 Agent 与固定团队。先选取 12 项代表任务作为拟定首轮样本：后端修复、前端交互、跨层功能、测试补漏各 3 项；具体任务、许可证、数据和费用窗口在执行前确定，12 项不是已生效基线。

| 维度 | 记录方法 |
| --- | --- |
| 完成质量 | 独立验收通过次数 / 有效尝试次数，记录样本规模、失败类别和未验证项 |
| 错误完成声明 | 未达验收却被报告完成的次数；保留原声明与实际证据 |
| 人工成本 | 澄清、干预、审查和返工耗时 / 次数，区分模型运行与用户等待 |
| 运行成本 | 实际模型尝试、用量来源、估算 / 上报费用、总耗时与预算耗尽 |
| 协作开销 | 冲突、重复修改、无效调用、过期测试和返修次数 |
| 执行边界 | 越界、取消未收敛、未授权调用和失控重试，不能被质量平均值掩盖 |

两种模式分别在独立副本运行，使用相同任务要求和可比资源上限，记录实际模型差异；执行顺序和人工干预也须记录。测试 / 审查独立于开发 Agent 的自报结果，不以批次元数据变化充当代码质量评分。

首轮只建立基线，再决定哪些任务适合团队及扩大条件。不能预先承诺省时比例、通过率提升或生产成熟度，也不因为等待模型新增模型裁判、训练或通用评测平台。
