## 单一状态权威

Go 平台拥有团队、任务与尝试的权威状态，决定执行和继续资格。协调模型只能提出计划、派单及返修建议；SDK 内部会话只描述一次尝试，不能自行把任务置为验收通过或恢复命令。

任务执行资格绑定当前账户、工作区成员关系、授权修订、需求 / 计划版本、团队版本、仓库基准、工具策略与预算。启动任务、执行工具、模型调用、集成候选和保存结果都重新验证相应资格；不能只在创建团队时检查一次。

## 拟定领域对象与归属

| 对象 | 核心内容 | 归属及约束 |
| --- | --- | --- |
| `TeamDefinition` | 不可变角色、模型引用、提示模板与执行策略版本 | 新团队领域；草案与生效版本区分，运行冻结精确引用 |
| `TeamRun` | 目标、验收、仓库基准、计划与授权版本、预算和交付状态 | Go 团队运行负责模块；作为一次开发交付的聚合入口 |
| `Task` | 负责人、依赖、输入 / 契约版本、路径与验收条件 | 同一团队运行内；共享契约明确单一负责人 |
| `Attempt` | 每次角色执行、模型快照、隔离副本、调用和工具结果 | 不覆盖旧尝试；新尝试需要显式原因和当前资格 |
| `ExecutionEvent` | 有序任务消息、系统状态、模型 / 工具动作的脱敏摘要 | 事件可追溯，不复制完整模型上下文或隐藏推理 |
| `ArtifactRef` | patch、manifest、测试与审查报告的身份、摘要和访问策略 | 引用拟新增开发产物负责模块，不把 SDK 文件路径当公开下载地址 |

团队首版拟为工作区资源。需要使用已有活跃应用承载 Gateway 调用归因，绑定规则及权限目录在实施前确定；不能借用旧 Agent Profile 的“已批准”状态取得写代码资格。

现有账户 / 成员仍归身份负责模块。单尝试已复用共享 SQLite，以独立 `development_attempts` 组件保存状态、请求、提议与事件，核对版本 / 摘要、原子消费和重启只读；不复制 Run / Session。当前管理员资格加逐任务精确计划确认才可签发，不借旧 Agent Profile 授权。具体表、Go 接线、凭据与事件读取见[尝试控制合同](../../../contracts/development-attempt-control-v1.md)；团队定义 / 共享额度 / 开发产物仍待新增合同。

## 拟定状态转换

下表描述完整团队流程，仍属设计词汇；已物化的单尝试控制子集固定 `active / cancel_requested / cancelled / completed / failed / outcome_unknown`，只描述控制工作，不代替任务验收或用户接受。枚举、预算事件及错误规则以[尝试控制合同](../../../contracts/development-attempt-control-v1.md)为准。

| 资源 | 主要状态 | 关键转换条件 |
| --- | --- | --- |
| 团队运行 | 待计划 → 待授权 → 排队 → 执行 → 测试 / 审查 → 待用户审阅 | 计划授权与当前资格有效；相关任务、候选与证据版本一致 |
| 团队运行终止 | 已取消、失败、阻塞、中断、结果未知 | 分别记录原因，不把停止调度直接视为进程已结束 |
| 任务 | 待依赖 → 可执行 → 执行中 → 待验证 → 通过 / 需返修 | 产物和验收证据齐备；角色自报完成只形成事件 |
| 尝试 | 排队 → 已认领 → 执行中 → 执行结束 / 失败 / 中断 / 结果未知 | 一次执行身份、实际外部影响和已确认结束证据 |
| 用户决定 | 未决定 → 接受 / 拒绝候选交付 | 绑定候选 manifest 摘要；不等同 Git 合入 |

采用预期版本 CAS 和原子任务认领，防止重复启动、重复确认和过期取消。HTTP 创建返回运行引用，任务与工具执行异步发生；客户端断线不自动取消或重新创建执行。

“暂停新增派单”只阻止后续任务，活动命令仍有独立状态；首版不承诺任意命令可安全暂停 / 恢复。权限撤销或授权过期时停止新增动作并请求终止活动尝试，已发生的隔离文件变更仍需记录，不能声称已回滚。

## 计划、授权与证据失效

计划变更保存新修订，列明受影响任务。已有授权不自动覆盖新增路径、工具、命令档案、模型、外网、依赖或预算。用户确认必须绑定精确修订；不根据聊天中的“继续”猜测授权对象。

候选代码用基准提交、文件树摘要或等价可重算身份绑定。测试证据必须记录实际命令、环境摘要、候选摘要、退出码和日志引用；审查必须读取相同候选和证据。实现、契约、测试或环境变化后，相关旧证据标为过期，不继续显示为当前通过。

返修由明确缺陷派生，保留原发现与尝试。集成冲突、缺少运行或部分证据保存失败不能合并为整体成功。首版不自动补偿提交、重放测试或猜测哪个旧产物应当采用。

## 事件与并发一致性

- 每个运行维护单调事件序号、唯一事件身份、来源尝试、发生 / 接收时间、关联资源与脱敏类型；消费者按游标增量读取，断线后按已确认序号继续读取。
- 事件重复接收须可去重；来源乱序或断档明确显示，不用后到达的报告覆盖更新状态。执行器重连只补交可验证的已有事件，不触发命令重放。
- 任务状态与关键领域事件采用同一事务或等价可核验的一致性方案。状态写入失败时停止新增副作用；不能只在 Web 时间线上显示成功。
- 实际工具影响与数据库事务无法原子回滚，必须以派发记录、执行身份、回执和产物核对表达间隙；无法确认时为结果未知。
- 并发控制保持有限：首轮最多两个代码写入角色，分别使用独立副本；不能把同一个可写工作树作为互斥失效后的兜底。

## 预算与用量

运行级预算包括任务数、并发、模型回合、修复轮次、墙钟时间、命令时限、token / 费用和产物体积。主专题中的数值只是待验证初值，不在本页再维护第二份默认表。

模型调用前原子预留输入估算及最大输出等上限，实际使用后结算。工具、压缩、重试和返修均进入归因；超时但提供方可能已处理的调用保留未决预留或明确估算，不立即全额释放并宣称零成本。单尝试已采用 Go 预留、整数 microUSD、未知量保留上界和迟到核账规则；SQLite 单尝试账目及真实定价读取已接线，原始 usage 按明确存在性处理；真实提供方原生传输仍待验证，团队共享预算未实现。

用量缺失显示未知，估算与提供方上报分开。运行内预算约束服务该功能，不扩展计费账本，也不重新打开既有应用跨页汇总的 `no_entry` 范围。

## 取消、崩溃与重启

1. Go 原子记录取消意图并停止新派发，向可信执行层传递取消。
2. 执行层停止 SDK 调用和隔离命令，处理子进程及容器；分别记录模型请求、命令与清理结果。
3. 只有取得结束证据后才标记已取消；超时、失联或无法确认的影响使用中断 / 结果未知，不只依据 PID 判断任务已经安全停止。
4. 重启读取持久记录，核对仍存活执行环境和已落地产物；默认不自动补跑、重放或恢复写入。
5. 用户可显式提出新尝试，重新核对基准、候选、副作用、权限与预算；它是新尝试，不覆盖原来的未知结果。

执行器生命周期与平台数据库关闭顺序必须明确：停止派发、请求取消、等待有界结束、记录未决项，再释放连接。首次单 Agent 阶段就实现这一基础，不推迟到团队阶段。本轮已实现持久停止状态、模型等待时每秒资格核对、上下文中断及关闭顺序；SQLite 关闭重开只读取，不恢复执行，旧实例凭据失效。固定响应已验，实际 SDK / 进程树 / 容器终止及其期限仍未实现，不能称完整取消验收通过。

## 正文、交付与保留

运行元数据、易失上下文、临时工具材料和用户显式保存的交付包分开管理。代码、日志、讨论和 patch 可能包含私有信息，必须有明确可访问范围与保留期限；不得自动把 SDK 完整 transcript 写入应用 Session。

交付包拟复用结果资产的显式保存和生命周期原则，但现有结果资产合同不自动支持开发包、文件下载或全部执行日志。阶段 0 须决定新增开发产物负责模块与现有资产引用的接线、体积 / MIME / 配额、导出权限及失败语义，不能直接把 bundle 塞进旧文本字段。

临时产物应在执行前设置保留期限和容量，清理只针对本运行拥有的资源。用户保存交付包前显示实际内容及敏感材料处理结果；原始密钥、提供方响应、隐藏推理和宿主机路径不得进入公开包。删除、延期和导出权限仍须在正式合同中确定。

## 必须验证的场景

覆盖重复认领、CAS 冲突、跨工作区 / 账户、权限撤销、事件断档、预算并发超限、模型用量缺失、取消失联、进程树未退出、写入后回执丢失、产物保存失败、过期测试及重启不重放。内存与 SQLite 首阶段验证；若选择 PostgreSQL 交付，再完成对应实现和独立证据，不预先声明双数据库支持。
