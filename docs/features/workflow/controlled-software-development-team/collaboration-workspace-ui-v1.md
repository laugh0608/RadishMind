# 受控开发团队：协作工作区与群聊交互 v1

更新时间：2026-10-31

状态：产品交互设计草案；尚无 Pencil 画板、视觉批准、React 页面或浏览器验收。

所属功能：[多 Agent 协同与受控软件开发团队](../controlled-software-development-team-v1.md)。状态事实由[团队运行负责模块](team-runtime-state-and-artifacts-v1.md)提供，本页只负责用户操作与投影，不建立前端调度或授权真相。

## 用户任务与页面归属

在正式 User Workspace 内规划“开发团队”功能入口，沿用本地账户、活动工作区、语义 token、国际化、导航与严格消费者。它承载一个开发任务从计划到候选交付的过程，不新增第五个一级产品面，不复用旧 Console 作为产品入口。

新页面是重要跨模块能力，实施前按 [UI 差异附录](../../../ui-addendum.md)评估设计等级与 Pencil 范围；团队配置、计划授权、运行 / 群聊和交付审阅至少需要明确桌面 / 窄屏状态。视觉通过与功能通过分别记录，当前不登记视觉批准或已分配的 S 编号。

| 区域 / 工作包 | 阶段 1 必需内容 | 后续内容 |

现有 `ConnectDevelopmentControl` / `ConnectDevelopmentArtifacts` 是内部 Go 接线；目前没有上述正式 Web 路由、任务级授权流程或运行协调交付。当前 Web 依赖中没有 diff 编辑器；首版可用可访问的只读文本 diff 与语义 token，不以新增编辑器依赖为前提。保存不表示接受、测试通过或允许 Git 合入，首版不增加没有负责模块支持的“接受候选”状态。

按 [Family UI 判定规则](../../user-workspace/radishmind-family-ui-productization-v1.md#判定维度)评分：结构 `1`、交互 `2`、边界风险 `2`、状态与窄屏 `2`、复用 `1`，合计 **8，A / 完整 Pencil**。复用现有工作区壳；设计一个任务运行 / 交付审阅桌面代表面，补计划确认、取消未确认 / 结果未知、证据过期及无法从桌面推导的窄屏切换。目标复核尺寸为 `1440×900` 与 `390×844`；不为每个表格和错误复制画板，不预占 S 编号。

阶段 0 要取得范围和视觉依据确认；阶段 1 要完成 React、严格 API 消费和真实浏览器验证。浏览器覆盖完整发起至保存 / 重读路径、权限撤销、跨工作区旧回调、取消收敛、刷新不重放、断线与失败恢复。已有固定响应后台验收不能代替视觉或页面验收。以下团队核心流程与三区布局是长期方向，阶段 1 只落实上表单 Agent 内容。

## 核心流程

| 操作阶段 | 用户看到与执行的内容 | 明确反馈 |
| --- | --- | --- |
| 选择输入 | 授权仓库、基准提交、任务目标、验收条件 | 来源不可访问、工作树有未纳入修改、基准不存在分别解释 |
| 配置角色 | 团队模板版本、角色职责、模型引用、工具 / 路径和预算 | 未支持的模型或工具组合阻止启动，不自动替换模型 |
| 审阅计划 | 子任务、依赖、接口约定、共享文件负责人和执行范围 | 显示确定的计划修订；需要修改时保存新版本 |
| 授权执行 | 代码副本、命令档案、网络、时间 / 费用和保留策略 | 确认绑定精确版本，范围变化使旧确认失效 |
| 跟踪运行 | 角色状态、任务依赖、阻塞、工具摘要与预算 | 已派发、实际运行、待验证分开，支持取消与停止新派单 |
| 审查交付 | diff、测试、发现、返修记录、未验证项 | 所有证据指向同一候选摘要，过期或缺失项明确标记 |
| 保存 / 决定 | 显式保存交付包、接受或拒绝候选 | 保存失败、用户决定与 Git 合入分别显示，不自动推送 |

阶段 1 即交付可用的单 Agent Web 流程：配置、确认、发起、取消、变更与证据、显式保存和重读。固定团队阶段再增加角色并行和交接；不先完成大量后台模块再补唯一用户入口。

## 三个协作区域

**任务与成员区**展示角色、模型配置版本、当前任务、依赖、状态、路径和阻塞。状态与进度取自服务端；不根据消息数量或“已完成”文本推算完成比例。

**讨论时间线**展示用户指令、角色报告、确认的计划修订及系统事件。消息可关联任务、尝试、契约或产物；不展示隐藏推理，不把 SDK 原始上下文直接广播给全部成员。等待、事件断档和内容被脱敏应有说明。

**交付审阅区**展示基准 / 候选、文件清单与 diff、实际测试、独立审查及已保存交付包。用户可以从一个测试结果精确定位受验代码，不能把当前 diff 与旧候选的通过证据拼在一起。

三者共享精确运行引用，不共享各自易失输入。窄屏可以按任务、讨论、交付切换，保持所选任务和运行身份清晰；关键取消、确认和错误不能只在桌面侧栏出现。

## 未来运行解释与轨迹呈现

阶段 1 的运行详情设计统筹[Gateway 路由决策解释与尝试轨迹](../../gateway/gateway-routing-decision-explanation-attempt-trace-v1.md)：先核对负责模块事实和身份关联，再显示冻结模型 / 价格 / 工具策略、实际模型请求、工具提议 / 入队 / 派发 / 完成、预算及停止原因。候选与实际执行分开，未知量不显示为零；没有可信关联的 Gateway 请求不得按时间或模型拼接。

历史轨迹回放后续只读消费原记录，不调用模型或工具，不替换模型、恢复执行或绕过确认。正式 Web 使用受权投影，不把可信 SDK 内部监听器或任务 bearer 暴露给浏览器。该项尚未实现，不推迟阶段 0 SDK、代码沙箱、归属终止和产物工作，也不以已有页面或 Magpie 截图登记本项目的视觉批准。

## 群聊和定向反馈

`@后端`、`@前端` 等是发送定向反馈的交互意图，由服务端解析为目标任务的用户消息或计划修订建议。文本不会直接授予权限、派发工具、改写验收条件或覆盖运行状态。

有明确任务归属的补充说明送达对应角色上下文。改变目标、接口、路径、工具、预算或网络范围时，界面引导为新的计划 / 授权修订，列明受影响任务，再由用户确认；不把群聊变成绕过治理的备用命令入口。

角色需要澄清时，显示问题、影响任务及阻塞原因。用户回答前，独立且已授权的其他任务可以按依赖规则继续；不得用等待时长代替用户批准。首版关闭角色自建团队、自由拉人和递归委派。

## 一致性、权限与隐私

- 切换工作区、账户、运行、候选或任务时，清除对应易失材料并拒绝旧请求迟到回调；复用项目既有 generation / surface 约束。
- 权限撤销后停止显示受保护内容，按服务端当前资格关闭继续 / 执行 / 导出动作；前端隐藏按钮不代替后端鉴权。
- 计划与授权确认绑定摘要；CAS 冲突要求重读，明确展示新旧差异，不自动覆盖用户修订。
- 事件断线按服务端游标重读，页面刷新不再次创建运行或执行工具；连接失败和执行失败分别显示。
- 显示模型名与配置引用、调用 / 用量来源，密钥只保留在可信后端；不进入 URL、浏览器持久化、群聊或错误提示。
- 用户需求、代码片段、草稿消息及未保存输出只在当前所需组件保留；团队讨论的持久化范围、期限和访问权限需在正式合同中明确，不自动复用应用 Session 全文存储。

## 必须覆盖的界面状态

| 状态 | 用户应能判断与执行的操作 |
| --- | --- |
| 未配置 / 真实空目录 | 缺少模型、仓库或团队版本时给出明确配置入口，不放入演示团队伪装已有资源 |
| 待计划 / 待授权 | 计划由谁提出、采用哪个修订、将触发哪些动作清晰可见 |
| 执行 / 等待依赖 | 区分活动任务、等待项、停止新增派单和仍在运行的命令 |
| 取消中 / 结果未知 | 告知尚未确认结束的动作、已保留成果和后续核对步骤，不显示安全完成 |
| 测试失败 / 证据过期 | 精确定位失败与受影响代码，提供受限返修或结束决定 |
| 部分保存失败 | 已保存和未保存的产物分开，不允许假冒完整交付 |
| 待用户审阅 | 同一候选的验收依据、未验证项、接受 / 拒绝及显式保存入口完整 |
| 历史只读 | 可读取已保存记录，原授权失效时不能继续工具执行；后续尝试需重新确认 |
