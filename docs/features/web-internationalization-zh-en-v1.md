# Web 中英国际化与本地化 v1

更新时间：2026-09-23

状态：A 阶段依赖安装、公共基座与 Prompt 主链展示迁移已实施；单元与构建验证完成，浏览器验收待单独授权。A 阶段尚未关闭，不能据此声明全站双语完成。

## 目标与职责

为 `apps/radishmind-web/` 建立统一的国际化（i18n）基础，使内部开发者能使用简体中文或英文完成应用创建、配置、审查、受控运行和结果恢复，并覆盖身份、管理、Gateway、Workflow 与评测等现有页面。完成标准是完整用户流程和状态的双语可用性，不是翻译文件数量。

本专题拥有界面语言选择、消息资源、术语、格式化、迁移顺序与双语验收规则；不成为业务数据、权限、运行语言或模型输出的所有者。功能行为继续以对应专题与 canonical schema 为准，视觉继续遵循 [UI 差异附录](../ui-addendum.md)。正文文档的中文优先规则继续由[文档语言治理](../document-language-governance-v1.md)维护。

项目所有者在手工测试阶段提出语言系统为下一重点，测试已按要求停止。尚未完成独立使用计时或答案质量审查，不能将本次优先级决定解释为已量化的用户效率结论。

## 范围与非目标

### v1 应完成的范围

- 简体中文 `zh-CN` 与英文 `en-US` 两套界面；本方案建议中文为最终默认值。只提供“简体中文 / English”两项，名称使用各自语言，不用国旗。
- 常驻与移动导航、页标题、按钮、表单标签、占位提示、帮助文字、状态、空态、加载态、错误与恢复提示、确认弹层、表格列名、图例和可访问名称。
- 现有 Web 认证入口、账户安全、工作区成员与邀请、管理控制台、应用各类型、Workflow / RAG / HTTP Tool、Gateway / API key、运行记录、结果与评测。
- 日期、数字、百分比、数量与复数的统一展示策略；复制与导出的协议值保持原样。
- 当前可达的离线展示和开发测试态页面也纳入覆盖；迁移中允许阶段性混用，但不得据此宣布整个 Web 已完成双语。

### 本轮不做

- 繁体中文、第三种语言、RTL、翻译 SaaS、远程语言包、自动机器翻译服务和在线翻译管理后台。
- 后端错误正文的多语言 API、`Accept-Language` 协议扩展、用户账户语言字段、跨设备偏好同步或数据库迁移。
- 自动翻译用户输入、应用名称、Prompt 源码、模型答案、RAG 文档、日志、结果资产、审计原文或历史记录。
- 改写 canonical 字段、枚举、资源 ID、错误码、摘要算法、URL 锚点、API 路径、配置键与权限标识。
- 英文化整个 docs、CLI、Go / Python 日志或测试数据；第三方代码和产品名不因本专题改名。
- 用国际化迁移同时推进大规模组件拆分、权限改动、运行时重构或新业务能力。

## 语言选择与状态边界

### 初始化和持久化

建议采用固定顺序：有效的本机显式选择 → 浏览器语言匹配 → `zh-CN`。浏览器 `zh` / `zh-*` 归入 `zh-CN`，`en` / `en-*` 归入 `en-US`；其它语言使用最终默认值。这不声称提供繁体中文或英式英语资源。

- 偏好只保存到当前 origin 的单一键 `radishmind.uiLocale.v1`，值只允许 `zh-CN` 或 `en-US`。不保存账户、工作区、输入、token 或消息参数；这是非敏感展示偏好，不放宽既有业务内容禁止持久化的边界。
- 读取无效值按上述顺序重新解析；读写被浏览器拒绝时保持本页内存选择，给出可翻译的“本次选择未保存”提示，不伪装为持久化成功。
- 不把 locale 放进稳定 URL，不建立服务器用户设置。退出登录保留本机偏好，切换账户和工作区不更改语言。
- 同源其它标签的有效偏好变化可更新展示；去重并禁止互相回写循环，不触发身份失效广播。删除偏好时重新应用浏览器匹配与默认规则。
- 首屏在挂载业务界面前解析语言和加载公共资源，同步设置 `document.documentElement.lang`。加载或初始化失败显示可操作的静态双语启动提示，不把错误吞成空白页面。

### 切换入口与行为

- 桌面入口放在现有导航底部、环境说明之前；窄屏放在菜单内、工作区选择之后。未登录认证页放在页头；具体组件边界见下文 A 阶段实施准备。不依赖仅在本地身份模式出现的账户按钮，不增加独立设置大页面或第二套导航。
- 切换即时更新已显示的标签、错误、空态和帮助文字，不要求刷新或重新登录。错误消息必须根据稳定状态重新展示，不能只翻译下一次请求。
- `uiLocale` 不参与标识当前工作区、应用和授权依据代次的 generation key、React `key`、路由或权限计算；所有使用展示标签作为 key 的落点在迁移时改用稳定标识。
- 切换不卸载当前表单，不丢失未保存 schema、草案、变量、光标上下文和结果，不清除一次性凭据，不发起新的业务读取、保存、模型调用或执行。
- 原有切换工作区、离开页面、撤销权限和卸载时的隐私清理仍生效；i18n 不扩大任何状态的寿命或复制其内容。
- 语言入口应支持键盘、明确焦点与读屏名称；变更完成可用轻量 live region 提示，不抢走编辑焦点。

## 技术方案

### 依赖选择与最小结构

采用 `i18next` + `react-i18next` 承担语言资源、插值、复数和 React 更新，使用浏览器 `Intl` 处理格式化。理由是现有页面多、动态状态多，长期维护完整消息规则有必要复用成熟库；不自研第二套翻译引擎。

具体版本、React / TypeScript 兼容性、锁文件变化与包体边界已在下文收口，本次安装已获授权并完成。只引入这两项直接依赖及其必要依赖，不默认增加语言检测、HTTP 资源加载插件、ICU、代码生成或 Vite 提取插件。

已建立的实施落点：

| 路径 | 职责 |
| --- | --- |
| `src/i18n/` | 唯一语言实例、偏好解析、初始化与资源类型声明 |
| `src/i18n/locales/{zh-CN,en-US}/` | 按功能命名空间组织的成对资源 |
| `src/i18n/formatters.ts` | 明确 locale、时区和单位的展示格式函数 |
| 现有产品壳与认证入口 | 共用语言选择控件，布局遵循 Family UI |
| 现有 feature 视图模型与展示边界 | 领域消息和状态映射；不增加全局万能错误 manager |
| `tests/`、`tests/e2e/` | 资源完整性、状态隔离、双语流程与布局验证 |

采用 TypeScript 资源对象与 `as const` 支持类型约束，沿用 Node 直接执行 TypeScript 测试的路径；资源为独立数据，不导入 React 或运行代码。以稳定语义键引用，不以中英文句子作为 key。统一使用 selector API，显式设置 `enableSelector: true`，由资源类型声明约束选择器与插值参数；不混用动态字符串路径，也不启用需要另行处理复数键的 `optimize` 模式。

命名空间按真实功能分组，例如 `common`、`shell`、`identity`、`applications`、`prompt`、`workflow`、`gateway`、`evaluation`、`admin`；同名多义词留在功能域，只有含义一致的控件文案才共享。不创建一个巨型平面字典，也不机械地为每个组件拆资源文件。

### 加载、类型与缺失消息

- 公共壳、认证入口及启动错误的两种语言资源随入口加载；其余资源沿用现有功能懒加载边界，随模块一并带入该功能的两种语言，不添加远程翻译请求。
- 已进入功能的语言切换不能重新触发 Suspense 卸载编辑器。A 阶段用真实未保存表单与等待响应的请求确认语言订阅不会改变生命周期。
- 两套资源必须保持相同语义键与兼容的参数契约；复数形式按各语言规则验证，不能机械要求英语和中文的复数后缀相同。
- 在编译和测试中拦截缺键、空值、参数遗漏、无用动态键与错误命名空间。禁止拼接任意字符串形成翻译路径，状态与错误码用显式映射表。
- 运行期只配置一个明确的 `zh-CN` 资源回退；缺键仍是缺陷，开发 / 测试必须暴露并阻止该批验收，不能靠中文回退宣称英文完整。
- 公共安全兜底消息两语都必须存在；目标语言与中文回退均缺键时，展示当前语言的通用说明，不能把内部 key 直接暴露给用户。诊断只记录命名空间 / key，不记录参数、凭据或用户正文，不启用自动上报与远程补词。
- 完整句子使用命名参数与复数资源，不把动词、对象、数量和后缀分别拼接。零值、单数、多数以及未知数量分别测试。
- React 以文本节点渲染插值；受信资源中的链接使用固定组件占位，不允许翻译内容生成任意 HTML、脚本或目标 URL，不使用 `dangerouslySetInnerHTML`。

### 视图模型、错误与协议

1. React 组件在渲染时翻译；模块顶层只保存语义键、状态或不可变数据，不能在 import 时计算一份固定语言字符串。
2. 已存在的本地 `summary`、`finding` 和步骤模型按其功能迁移为可在展示时解析的稳定消息标识与安全参数，或由组件依据稳定状态直接生成文案。纯协议校验与领域代码不依赖 React hook 或可变全局语言实例。
3. 服务端 `failure_code`、状态码和结构化参数保持原样，功能展示层映射到中文 / 英文说明，同时在诊断区保留可复制的原始错误码与请求引用。
4. 未知错误码显示通用失败说明和恢复建议，不按服务器自然语言字符串做匹配，也不猜测“未调用模型”“保存成功”等业务事实。只有已知状态语义才能作这些断言。
5. 服务端原始 summary、审计原文或历史自然语言只有在既有契约允许公开且确有诊断用途时才展示，并标为原始诊断；不默认把任何未映射英文错误列为翻译豁免。
6. A 阶段盘点缺少稳定 code / finding 标识的用户提示：能由现有状态表示的在展示层处理；必须新增协议字段的单独列明影响并重新确认，不在文案迁移中暗改 API。
7. 已保存的数据、模板、模型 locale、结果正文和 digest 不因切换语言发生变化；新模板的示例内容也不随界面切换重写。若未来提供语言化模板，作为独立产品功能评审。

## 术语与格式规范

### 初始术语表

| 稳定概念 | 简体中文显示 | 英文显示 | 说明 |
| --- | --- | --- | --- |
| workspace | 工作区 | Workspace | 与账户或 tenant 分开 |
| application | 应用 | Application | 不称为模型 |
| template / draft | 模板 / 草案 | Template / Draft | 模板版本与配置草案区别明确 |
| immutable version | 不可变版本 | Immutable version | 不暗示可以覆盖修改 |
| candidate / review | 候选版本 / 审查 | Candidate / Review | 审查通过不等于部署或激活 |
| approve candidate | 批准候选版本 | Approve candidate | 不翻译为“立即发布” |
| runtime assignment | 运行绑定 | Runtime assignment | 指向精确受审资源的运行授权关系 |
| activate / replace / revoke | 激活 / 替换 / 撤销 | Activate / Replace / Revoke | 三个独立动作，保留确认语义 |
| controlled invocation | 受控调用 | Controlled invocation | 不暗示自动重试或无限执行 |
| session / turn | 会话 / 轮次 | Session / Turn | 历史元数据不等于完整对话恢复 |
| result artifact | 结果资产 | Result artifact | 显式保存，不与 Run 记录混为一谈 |
| run / evaluation | 运行 / 评测 | Run / Evaluation | 不等同于模型答案质量达标 |
| version conflict / authority drift | 版本冲突 / 授权依据变更 | Version conflict / Authority drift | 错误码和版本值保留可复制原文 |
| requires_confirmation | 需要确认 | Confirmation required | 显示标签可翻译，协议字段与布尔值不变 |

完整术语按对应功能专题确认，禁止为了文案短而弱化权限、作用域、原子性、显式保存或人工确认。技术标识符可在中文界面保留，但周围说明要可读，不把整段工程英文算作术语豁免。

### 时间、数字与输入

- 普通展示明确采用界面语言与浏览器本地时区；审计、安全、计划调度等现有 UTC 展示保留 UTC 并标明时区。界面语言不决定时区、计划时间或夏令时规则。
- 保留原始时间戳供精确详情 / 复制使用；无效日期不能抛到整个页面或伪装当前时间，缺失值显示本地化“未知 / 未提供”。
- 使用 `Intl.NumberFormat` 处理计数、百分比和已知单位；金额只采用服务端给定币种与数值，不做汇率换算，不补猜缺失价格或用量。
- 大整数、精确小数和统计分母保持现有数值契约，不为格式化转换为失真的浮点数；缺失不能当作 0。
- 表单值、JSON、代码示例、导出和请求数字仍按既有机器格式编辑与提交；v1 不引入逗号小数解析或本地化 JSON 数字。
- 排序、分页、版本比较与资源 ID 排序沿用既有规则；仅展示文案变化不能改变协议排序或调用 `localeCompare` 重排 canonical 数据。
