更新时间：2026-10-31

状态：统一运行档、命令、Web 接线、Docker 资产及冷备份恢复已实现；2026-10-31 已完成 macOS 宿主机 Chrome 的首次使用、Prompt / Workflow、显式保存、冷重启和新目录恢复验收，并修复实际阻塞。`linux/arm64` Docker 构建 / 运行、挂载限制、冷重启及容器与宿主机备份迁移也已完成技术验收；Windows PowerShell、`linux/amd64` 容器与独立用户验收尚未完成，真实模型窗口继续暂停。

## 决策与用户目标

项目所有者在全项目复审后批准整合未来规划。本专题成为当前唯一产品主线，替代此前跨版本回归审查的优先排期。审阅依据见[工程健康专题](../../platform/engineering-health-productization-remediation-v1.md#2026-10-26-全项目复审交付后移与开发循环)，长期顺序见[路线图](../../radishmind-roadmap.md#后续开发方向2026-10-26)。

首轮用户是项目所有者及内部开发者。交付目标是：在本机完成一次明确配置后，通过正式 Web 创建或打开 AI 应用，编辑并受控运行，显式保存有用结果；关闭并重新启动后，继续使用原账户、应用、版本、应用会话和已保存结果。先证明这条路径能够持续使用，再用真实任务判断模型效果和后续功能投入。

这是一项跨启动、身份、存储和用户工作区的交付工作，不另建产品面。已有[应用开发工作区专题](application-development-workspace-release-readiness-review-v1.md)继续负责页面编排事实，本专题负责从启动到恢复的完整交付及缺口。

## 首轮交付范围

- **一个本机入口。** 面向回环地址上的个人 / 内部开发使用，正式 Web 为用户界面。展示运行模式、配置错误及明确的关闭方式；演示资源可识别，不静默替代真实用户资源。
- **一份明确配置。** Go Platform、Python Runtime 和 React Web 保持现有职责。优先复用既有本地 Session 与 SQLite；不重建账户、数据库或通用配置框架。既有 PostgreSQL 能力保留，首轮不要求新增双数据库部署产品。
- **一条可保存的任务链。** 首个验收任务复用[故障诊断素材](prompt-application-dev-test-usage-guide.md#内部故障诊断试用)，覆盖 Prompt 编辑、受控运行、结果审查与显式保留；同一配置下验证 Workflow 创建 / 打开、版本和运行链。两者共用交付基础，保持各自执行规则。
- **可解释的恢复。** 再次启动读取同一目录与作用域，不覆盖旧数据、不静默重置账户、不切换到内存或固定样本。恢复应用与已保存证据不自动重跑历史输入或恢复中断执行。
- **可维护的本地数据。** 明确配置与凭据来源、数据目录、备份与恢复步骤、版本兼容和迁移失败处理；不要求首轮开发通用迁移管理平台或自动云备份。

功能实现应复用现有领域模块。只有明确发现现有契约无法表达交付需求时，才提出必要的 API / schema 变更；不得为了统一入口改写既有版本、授权、确认、并发或保留语义。

## 具体设计需要确定的内容

在本专题内完成以下设计，不另开一串准备状态专题。设计范围明确后连续实施，普通子步骤不重复申请同一授权。

1. 启动入口、模式名称、进程归属与关闭方式；首次初始化和再次启动如何区分，哪些检查可在启动前完成。
2. 配置来源与优先级、固定数据目录、共享 SQLite 的接线、领域开关组合及错误提示；确认旧开发命令的兼容行为。
3. 本地账户初始化、登录 / 登出、活动工作区和角色的使用路径；复用既有 Session，不使用开发身份头冒充用户认证。
4. 提供方 / 模型配置与凭据引用，确定性验证模式与真实模型模式的明确区分；配置缺失时不自动访问远端或替换模型。
5. Prompt / Workflow 所需资源如何由用户建立或明确导入；列出 Session、Run、Result Artifact 各自保留内容与重启恢复依据。
6. 数据备份一致性、恢复前检查、版本兼容与迁移失败处理，以及哪些操作会影响用户数据；确定必要的页面、帮助和错误恢复改动。

上述六项已具体化并由项目所有者确认实施范围。本轮按授权连续实现，普通步骤不重复申请授权；服务、镜像构建与容器运行仍需各自运行窗口。

## 具体启动与交付方案（2026-10-26）

以下契约已按确认范围实现，具体命令及恢复后的路径调整见[运行指南](../../platform/local-persistent-workbench-operations-v1.md)。用户要求参考 Radish 的 Docker 与配置实践，本方案吸收其配置分层、持久目录、健康检查、升级前备份和失败停止方式；不复制其多库、Redis、Auth / Gateway 服务拆分或开发默认账户。

参考来源为 [Radish 配置边界](https://github.com/laugh0608/Radish/blob/master/Docs/guide/runtime-configuration-boundaries.md)、[本地 Compose](https://github.com/laugh0608/Radish/blob/master/Deploy/docker-compose.local.yaml)、[部署 Compose](https://github.com/laugh0608/Radish/blob/master/Deploy/docker-compose.yaml)、[前端镜像](https://github.com/laugh0608/Radish/blob/master/Frontend/Dockerfile)与[迁移发布编排](https://github.com/laugh0608/Radish/blob/master/Docs/guide/production-database-migration-deployment.md)。它们用于参考设计，本项目可用性仍由自身实现和验收证明。

### 1. 运行拓扑与访问地址

采用一个 `local-workbench` 运行档，两种载体使用相同业务配置、身份和数据格式：

```text
浏览器 → 同一来源的 Web 静态资源 / 工作台公开配置 / 既有 API
                      Go Platform
                      ├─ 本地 Session 与领域服务 → 一个 SQLite 文件
                      └─ 受控 stdio 工作进程 → Python Runtime → 显式选择的模型
```

- 宿主机默认只监听 `127.0.0.1:4100`。日常使用已构建的正式 Web，由 Go 标准库 HTTP 服务提供；不依赖 Vite 开发服务器常驻，不另起反向代理或 Node 服务。
- Docker 使用一个 `workbench` 服务，内部监听 `0.0.0.0:7000`，只映射 `127.0.0.1:<工作台端口>:7000`，默认工作台端口 `4100`。镜像包含正式 Web 产物、Go Platform、既有身份初始化命令和 Python Runtime。
- 浏览器的 API 基址统一取当前来源；容器内部地址不能进入浏览器配置。`public_origin` 是完整浏览器来源，端口变更必须同步；使用错误来源应明确拒绝，不自动切换到 `localhost`、旧 `7000` 或跨来源服务。
- 不启动旧 Console、Radish Auth、Redis 或 PostgreSQL。现有开发 / 数据库专项入口保持兼容；本运行档不改变它们的能力或生产边界。
- `web-live`、`web-offline` 等旧命令继续保留并明确标注开发 / 演示用途，`workbench` 为独立选择，不静默改变原默认行为。

选择由 Go 提供静态资源，是因为当前只有一个对浏览器服务的后端和一套用户 Web，无需为交付新增反向代理依赖。此职责仅限资源分发，不在 Go 中重写前端或新增业务聚合层。

### 2. 配置来源、数据目录和凭据

复用 `RADISHMIND_PLATFORM_CONFIG` 与现有配置加载器，增加运行档及工作台所需字段。固定优先级为：**代码默认值 < 运行档默认值 < 显式 JSON 配置 < 显式环境变量**；最后验证运行档不变量。覆盖为错误身份、内存存储、演示来源或非法监听范围时应拒绝，不静默改回默认值。

宿主机默认配置文件为 `var/workbench/platform.json`；相对数据和凭据路径以配置文件目录解析，不受当前工作目录影响。下面是已支持的配置形状；完整宿主机样例另含虚拟环境 Python 路径：

```json
{
  "runtime_profile": "local-workbench",
  "listen_addr": "127.0.0.1:4100",
  "local_persistence_mode": "sqlite_dev",
  "sqlite_dev_database_path": "data/radishmind.db",
  "provider": "mock",
  "model": "radishmind-workbench-mock",
  "workbench": {
    "public_origin": "http://127.0.0.1:4100",
    "tenant_ref": "tenant_local",
    "workspace_id": "workspace_local",
    "environment": "development",
    "web_assets_path": "../../apps/radishmind-web/dist"
  }
}
```

| 配置类别 | 唯一职责与规则 |
| --- | --- |
| 启动 JSON / 环境变量 | 监听、浏览器来源、身份作用域、数据路径、模型接入和资源目录；不保存用户应用或批准记录 |
| 工作台运行档 | 展开必需功能开关并验证组合；Go 配置层是单一来源，Shell、PowerShell 和 Compose 不分别维护几十个领域开关 |
| SQLite 领域记录 | 账户、权限、应用、版本、会话元数据、运行和显式结果；网页仍经各自领域 API 修改 |
| Web 公开配置 | 只投影浏览器需要的来源、作用域、技术模式及可用功能；不包含密钥、凭据路径、数据库路径或提供方 URL |
| Compose `.env` | 只负责镜像标识、宿主机端口、挂载路径及 UID / GID 等部署差异；不另存应用业务配置 |

宿主机目录固定为 `var/workbench/{platform.json,data/,secrets/}`，备份默认放在独立的 `var/workbench-backups/`。Docker 默认使用 `deploy/workbench/{platform.json,data/,secrets/}`，备份在 `deploy/workbench-backups/`；两者默认隔离，禁止同时打开同一个数据库，迁移载体通过备份 / 恢复完成。

工作台配置需拒绝未知字段、重复 JSON 键、路径类型错误和相互冲突的值；原有非工作台配置的兼容规则保持。运行档不得自动读取旧 `tmp/radishmind-platform.local.json`。原有 Python 入口可读取仓库根 `.env`，工作台已显式关闭这条隐式加载路径，并只向子进程提供已解析的模型配置；其它开发 / 实验入口保留原行为。

新增 `api_key_file` 作为后端凭据引用，路径以配置目录为基准，内容只在后端读取并经既有受控渠道交给 Python。工作台禁止把密钥写入 JSON 或前端构建参数；`api_key_file` 与 `RADISHMIND_PLATFORM_API_KEY` 同时提供时拒绝，不选择一个静默覆盖。普通配置检查只验证引用和可访问性，摘要只输出已配置 / 未配置；启动再读取值。凭据轮换通过替换文件并重启生效，不自动修改应用授权。

首轮模型配置支持现有 `mock` 和显式 `openai-compatible` 路径。真实模式必须填写模型、地址及所需凭据，不自动探测远端、下载权重或降级到 mock；现有其它适配器不删除，未验收的组合不计入本工作台首轮完成声明。

### 3. 功能开关和真实数据来源

| 组 | 本运行档的决定 |
| --- | --- |
| 身份与存储 | 开启本地身份 HTTP，认证固定 `local_session_dev_test`，持久化固定聚合 `sqlite_dev`；不逐项设置组件 `*_STORE` |
| 应用主链 | 开启 Application Catalog、Configuration Draft、Publish Candidate、Prompt Template / Runtime 的既有 HTTP / 写开关 |
| Workflow | 开启 Saved Draft、Definition Release 与受控 Executor；保留现有校验、审查与显式激活 |
| 会话与结果 | 开启 Application Session、运行历史及既有显式结果保存 / 资产库链；默认不持久化完整答案 |
| API 调用 | 开启既有 API Key 生命周期，Gateway 固定 `api_key_dev_test`；Web Session 不自动成为模型 API 密钥 |
| 提供方选择 | 首轮采用已有 `static_config`，从显式后端模型配置产生可用选择；不同时开启管理端路由快照真相源或自动批准 Provider 路由 |
| 暂不加入 | Schedule runner、真实 OIDC、Agent / RAG / HTTP Tool 执行、模板分发、自动回退、配额 / 计费扩展与生产能力 |

现有 `ControlPlaneRead` 默认仍有 `fake_store_dev`，而部分用户资源已有独立真实负责模块。工作台不得把旧假数据列表混入用户首页：主任务只消费真实 Catalog、Definition、Session、Run、Result 与身份来源；没有真实来源的管理 / 证据页面在本运行档不开放，相关旧只读接口不能返回伪造的租户、审计或配额。开发演示模式仍可使用原样例。

这不是删减已有功能，而是确定首轮统一交付的可验收范围。首轮以普通 Prompt 和基本 Workflow 证明持久技术链；内置 mock 是有限的 Copilot 固定响应，不能假设它支持任意 Prompt 输出合同。五字段诊断等结构化正向场景使用明确标注的隔离固定响应提供方验证；真实模型任务效果继续待窗口恢复，不在产品中隐式启动测试提供方。

### 4. Web 运行时配置与静态分发

已新增 `GET /workbench-config.json`，使用一份版本化 canonical schema 与严格 Go / TypeScript 类型。最小字段为 `schema_version`、`public_origin`、`tenant_ref`、`workspace_id`、`environment`、`provider_mode` 及受限功能列表；不提供账户清单或秘密配置。

- Web 入口先读取并严格验证配置，再加载 App 与其配置消费模块；不能在模块顶层先用旧 `VITE_*` 默认值建立消费者。
- `local-workbench` 构建只固化运行档，不固化端口、租户、工作区或后端地址。配置缺失 / 非法时显示初始化错误和重试，不回退离线 fixture。
- 保留既有开发构建的 `VITE_*` 路径；工作台消费者统一从经验证的运行时配置获得同源地址、作用域和认证方式，不通过动态改写 `import.meta.env` 接入。
- 配置、入口 HTML 不缓存；带内容哈希的资源可长期缓存。配置必须与服务端实际开关对应，但前端功能列表不承担权限判定。
- 静态分发仅服务构建目录中的允许资源；API、认证、健康与公开配置路由优先，未知 `/v1/*` 继续返回 API 错误，不能返回 SPA HTML。拒绝目录遍历、符号链接逃逸、隐藏文件和任意宿主机文件读取。

### 5. 首次进入与管理员初始化

复用既有“注册账户 → 显式初始化管理员”的边界，不将第一个注册用户自动升为管理员，也不增加未认证的 HTTP bootstrap。

1. 用户准备依赖和配置，显式执行 `init` 建立空数据库，然后启动工作台。
2. 在正式 Web 注册自己的账户；登录成功但没有成员关系时，显示真实未加入状态和当前 `user_id`，不展示演示应用。
3. 用户停止当前工作台，在终端显式执行 `bootstrap-admin --user-id <当前账户 ID> --audit-ref <本次审计引用>`。作用域从同一配置读取，命令输出目标供核对，在 Go 子命令内复用既有 `BootstrapLocalIdentityWorkspaceAdministratorDevTest` 领域初始化逻辑（与原独立 CLI 共用），保留精确账户、单胜者、重复拒绝和最后管理员保护。
4. 重启并登录后，进入已授权工作区，手动创建应用与所需模板 / Definition；正常使用不再执行初始化。

密码只由注册 / 登录页面提交；配置文件、Compose、镜像和初始化脚本不保存固定管理员或默认密码。首轮允许回环 HTTP 的既有 `_dev` cookie 策略，保留 HttpOnly、SameSite 与 Origin / CSRF 校验；不引入共享网络或生产 cookie 声明。

配置中的 tenant / workspace 只是启动目标，不授予任何权限。改动作用域只会读取新目标，不复制旧成员或资源；重新初始化也不能覆盖已有管理员。账户创建 / 成员关系失败沿用原领域错误，不用开发身份头兜底。

### 6. 初始化、启动、升级与关闭

已通过 `start.sh workbench <动作>` 与等价 PowerShell 入口提供下列动作；包装脚本只负责定位与调用，配置校验、数据操作和领域行为由 Go 负责。Docker 复用同一命令语义和二进制，包装器只转换载体。

| 动作 | 明确行为 |
| --- | --- |
| `check` | 校验配置、来源、路径和构建产物，以有界 Python 子进程检查版本及 `jsonschema`；不建 / 打开数据库、不迁移、不启动工作进程池、不调用模型 |
| `build` | 使用已安装依赖构建 Web 与 Go；Docker 构建单独显式选择。不隐式安装依赖、拉取镜像或下载模型 |
| `init` | 只接受尚无数据库的目标，以临时文件应用现有完整 SQLite migration 集，成功后发布新库；已存在目标拒绝覆盖。不建账户、不提权、不填充业务样例 |
| `serve` | 前台启动；数据文件缺失、迁移标记未知 / 摘要不符或有待应用迁移时拒绝，提示正确的初始化 / 升级动作；端口占用不接管其它实例 |
| `bootstrap-admin` | 停服后使用同一配置调用已有一次性身份初始化命令；不改变普通注册流程 |
| `backup` | 停服并取得数据目录独占权后生成一致备份及清单；运行中、目标存在或校验失败时拒绝 |
| `upgrade` | 停服、验证当前库并成功备份后，显式复用既有迁移执行器；失败保留现场且不自动重新启动 |
| `restore` | 校验备份并恢复至新的空目标目录；不覆盖现用目录，不自动启动、不重放历史输入 |

宿主机默认数据入口为 `./start.sh workbench serve --config var/workbench/platform.json`，等价 PowerShell 由 `start.ps1` 提供。命令帮助和 Go 参数测试已补齐；PowerShell 入口尚未运行验收，不由 Windows 二进制交叉编译推定包装脚本可用。

数据目录独占约束覆盖工作台服务、bootstrap、备份、升级和恢复，宿主机与容器不得绕过；正常退出释放，异常退出的锁处理必须核实实例已停止，不能只根据不同容器的 PID 判死。旧开发入口不可与工作台共用数据目录。

2026-10-31 开发控制基座新增共享 SQLite 组件 `development_attempts / 0001_development_attempts`（四张状态 / 请求 / 提议 / 事件表），不默认启用执行通道。此前已初始化的工作台需要停服、备份并显式 `upgrade` 后使用新构建；旧构建遇新增标记继续拒绝，不能直接回退程序或改写标记。历史验收所记录的表数与迁移摘要保留其当次含义。本轮没有升级日常工作台目录。

当前 SQLite `Open` 会自动迁移。工作台新增只读预检，`serve` 只有标记与当前迁移集合完全一致才进入现有运行时；`init` / `upgrade` 才允许应用迁移。保留原开发入口的自动迁移行为，不复制 SQL 或另建迁移引擎。版本回退遇到未知迁移应停止，不自动执行 down migration。

宿主机以前台进程接收 Ctrl+C / SIGTERM，关闭 HTTP、取消活动请求、停止 Python 工作进程并释放数据库；不使用隐式后台启动。Docker 采用 exec 形式启动 Go，保留信号传递，停止宽限期覆盖既有 10 秒 HTTP 关闭及工作进程回收。超时强制停止后必须记录中断，重启不补跑；本地 Compose 默认不配置自动重启循环。

### 7. Docker 资产与挂载

已新增 `deploy/docker-compose.workbench.yaml` 与非密钥样例 `deploy/.env.workbench.example`，保持旧 local / test / prod Compose 的语义。工作台 Compose 项目名独立，端口和数据目录显式绑定；本轮不新增发布 workflow 或推送镜像。

| 挂载 / 镜像内容 | 决定 |
| --- | --- |
| `/etc/radishmind/platform.json` | 配置只读挂载，沿用同一 JSON 格式；容器路径由配置明确给出 |
| `/var/lib/radishmind` | 唯一可写的持久数据目录，包含 SQLite 及其侧文件；停止 / 删除容器保留目录 |
| `/run/secrets/radishmind` | 凭据文件只读挂载；不使用 Docker build arg、镜像 ENV 或前端变量存密钥 |
| `/backups` | 仅备份 / 恢复一次性命令挂载，日常服务不需要写备份目录 |
| 标准输出 / 错误 | 脱敏运行日志，由 Docker 有界轮转；不记录密码、答案正文或提供方原始错误 |
| 工作台镜像 | 多阶段构建正式 Web 与 Go，运行层保留现有 Python；同时包含显式身份初始化命令，不含数据、秘密、模型权重或开发依赖目录 |

容器使用非 root 用户；宿主机准备的目录权限必须与显式 UID / GID 相容。启动预检发现不可写即停止并说明目录，不自动递归 `chown`、放宽到全员可写或改用临时数据库。SQLite 目录与文件维持既有权限规则。

旧 Platform Dockerfile 固定 `GOARCH=amd64`，且未在依赖下载层复制 `go.sum`，本轮未改变它。新增工作台 Dockerfile 使用目标架构参数，在依赖层复制 `go.mod` / `go.sum` 并执行校验；Web 使用现有 lockfile。`.dockerignore` 已排除 `var/`、工作台数据 / 凭据 / 备份和本机配置，避免构建上下文带入用户材料。不能把“支持目标架构构建”写成 amd64 / arm64 都已运行验收。

服务启动前检查 SQLite 兼容性与 Web 产物；容器健康探针随后仅访问 `/healthz`，不持续执行数据库完整性检查，也不发起模型请求。启动检查或配置失败会阻止服务建立；探针正常不代表后续存储操作、真实模型或答案质量均正常。

### 8. 备份与恢复契约

首轮只提供冷备份。先明确停止写入并取得独占权，完成 SQLite 完整性 / 外键与迁移标记检查，再用一致快照生成独立数据库副本；不能在运行中只复制 `.db` 而忽略 WAL。复用 SQLite 能力，不把二进制备份存进应用结果库。

备份目录保存数据库快照、非密钥配置快照与清单。清单包含格式版本、创建时间、来源构建标识、迁移集合、文件 SHA-256 和作用域，不包含秘密值或真实模型输入 / 输出摘要；数据库本身含用户数据，仍是私有材料。凭据文件不纳入普通备份，恢复时显式重新挂载原凭据或新凭据。原生构建标识记录 Git 提交及未提交状态；容器使用显式 `BUILD_VERSION`，默认未标识值不等同镜像摘要，程序不自动查询 Docker 镜像身份。

恢复先检查清单版本、完整性、校验和、文件集合与路径边界，再写入新的空目录并复验数据库。旧库、失败现场和原备份均保留；只有验证成功后才允许用户切换配置并显式启动对应版本。未来版本的数据库不能直接交给旧二进制，发现不兼容即停止。

恢复的是备份时点：之后的修改、成员撤销或密钥吊销不会凭空保留。恢复结果需明确这一时间边界，用户重新登录并核对账户 / 成员 / API key 状态后继续；不声称备份是跨时间的权限合并，也不自动重新执行已保存任务。

技术可用、任务有效、共享交付是三个独立结论。真实模型试用继续暂停，恢复后在本工作台中使用明确任务集，分别记录结构合规、事实正确、建议有用、人工修改、延迟及可信用量。现有 Comparison / Campaign 的元数据分类不充当答案质量评分。

模型窗口未恢复时，可完成不依赖真实模型的设计、实现和技术验收；完成后如实停在质量待验证，不为填补等待期自动增加功能。技术里程碑关闭后，依据使用证据选择一个后续问题：结果质量、重复版本审查、共享交付或实际业务接入。

[跨版本回归审查](application-cross-version-regression-review-dev-test-v1.md)保留为候选。当持续使用证明手工逐对比较妨碍版本迭代，并且测试材料与审查依据明确时，再决定其排期；Workflow 优先只在该候选获选后适用。

## 非目标与停止线

- 不改变 Go / Python / React 分工，不借交付之名进行全量后端拆包、协议重写或新语言栈迁移。
- 不宣称公开生产就绪；本地 Session / SQLite 交付不自动满足共享网络认证、生产密钥、配额 / 计费或进程监管要求。
- 不增加跨版本评测、模型裁判、Agent 自治循环、长期记忆、训练、生图后端或新的后台调度。
- 不开放业务写回、自动确认、自动发布、历史重放或 `write_allowed_by_policy`。
- 不自动下载模型 / 数据、安装依赖、启动常驻服务、上传、打包或部署；不修改外部项目工作区。
- 不预先承诺尚未验证的用户收益，不将计划、固定响应、浏览器验收与真实模型质量混为一个完成结论。
