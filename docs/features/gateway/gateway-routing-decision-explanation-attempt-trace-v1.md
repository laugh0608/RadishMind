# Gateway 路由决策解释与尝试轨迹 v1

更新时间：2026-10-31

状态：已纳入未来规划，尚未实施、未取得视觉批准。当前受控软件开发团队的 SDK / 隔离执行顺序保持；本专题不启用新路由策略、真实提供方调用或请求重放。

## 定位与用户任务

让内部应用开发者和有权管理配置的管理员看懂一次请求如何选择模型、实际调用了谁、为什么继续或停止，以及实际用量和费用有哪些已知 / 未知部分。入口归属现有 Model Gateway、Request History 与开发运行详情，不增加一级产品面或另建 Console。

具体任务：

1. 从一个请求或开发尝试进入详情，识别调用来源、作用域、当次冻结配置和实际执行路径。
2. 区分允许的候选、实际派发、未派发、成功、失败、取消和结果未知，判断为什么使用或未使用备用目标。
3. 从一次尝试精确进入其现有失败、用量、成本或工具事件，核对结果而非猜测原因。
4. 断线或重启后只读回历史事实，必要时按事件时间回看过程，不再次调用模型或工具。

项目所有者提供 Magpie 界面后，已选择借鉴其路由链、原因说明、连续调用解释和历史呈现。独立用户尚未验证这些呈现能减少多少排查时间，收益目标须先取得任务基线，不预填提升比例。

## 与现有能力的关系

| 负责模块 | 当前已有事实 | 本专题的未来消费方式 |
| --- | --- | --- |
| Admin Provider Route | 草案 / 候选 / 审查 / 激活、不可变 generation / digest 与精确目标 | 显示当次已保存快照及来源；配置编辑仍走原管理流程 |
| Gateway Provider Attempt | 显式允许的有限 unary 主备尝试、逐次准入 / 价格与类型化失败 | 展示原计划、实际尝试及停止事实，不重新排序或扩大回退 |
| Gateway Request History | 根请求、尝试明细、状态、耗时、已报告用量和成本覆盖 | 复用记录、权限、分页和精确详情交接，不建立第二套历史仓库 |
| 单尝试开发控制 | 当前资格、冻结模型 / 价格 / 工具策略、SQLite 事件 / 预算、取消与未知量 | 在未来正式 Web 运行详情中投影；模型请求、工具提议、入队、派发与完成分别展示 |
| 应用运行观测 | 两种既有来源的当前窗口观测，后续仍为 `no_entry` | 不扩展为全局汇总，不通过时间、模型或相同文本猜测关联 |

Gateway 根请求、Provider attempt、开发 Attempt 与工具请求是不同身份。只有负责模块已经提供明确、可验证的关联时才画父子连线；缺少关联就分别展示并标明不可关联。共享的是呈现规则，数据与授权仍由各自负责模块拥有。

现有受控主备见[Provider Attempt 专题](provider-attempt-controlled-retry-fallback-execution-dev-test-v1.md)，开发侧见[尝试控制合同](../../contracts/development-attempt-control-v1.md)。本专题不把开发专属通道自动接入旧主备执行器，也不把旧建议协议扩成代码执行协议。

## 核心界面与证据规则

### 调用链与事件明细

Gateway 视图拟展示：调用方 → 当次路由快照 → 候选与实际 Provider 尝试 → 结果 / 用量。开发视图拟展示：已确认计划 / Attempt → 冻结模型请求与工具事件 → 候选结果 / 预算。两种视图保留来源标签。

- 已配置的候选与实际调用采用不同样式及文字；不能把备用目标画成已经调用。
- 主图显示关键路径，详情保留请求身份、序号、配置修订、摘要和原因；不要求拖动节点编辑配置。
- 原因说明由后端明确事实和枚举生成确定性文案；不额外调用模型编写解释，不展示隐藏推理。
- 未记录的“为何未选”显示证据不足；不能用当前配置倒推历史决定，也不能仅因最终成功推定中间没有失败。
- 已有记录不足以支持关键原因时，先评审负责模块的脱敏决策记录与版本兼容，再实施必要合同扩展；本规划不预设新 API 或 schema。

### 指标与未知值

| 指标 | 采用条件与展示边界 |
| --- | --- |
| 次数 / 改道 / 错误 | 先定义根请求、实际尝试、用户收到的错误各自分母；当前分页窗口必须标明覆盖，不冒充全历史 |
| 总耗时 | 使用已有真实记录；网关与提供方耗时沿用各自可用性标记 |
| 首 token 时间 / 输出速度 | 有可信流式时间点和明确计算区间才展示；非流式总耗时不能冒充首响或生成速度 |
| token / 费用 | 实报、缺失、不适用和价格覆盖分开；保留逐次成本及未知部分，不把缺失量计为零 |
| 缓存命中 | 取得提供方可信输入 / 缓存计数后，明确计算口径；输入 token 缓存比例不表述为答案缓存或请求成功率 |
| 配额 / 余额 | 应用请求配额、开发尝试预算、厂商账号余额分别标注来源和时间，不混用或跨单位相加 |

首批只采用已有且能解释的字段。当前 Request History 和开发回执不因此被声明已经具备首响、输出速度、缓存计数或厂商余额；这些扩展分别按真实接入证据决定。

### 历史轨迹回放与使用边界

“回放轨迹”只根据既有事件序号、时间和尝试记录重现展示，暂停 / 加速均只影响界面。读取、刷新、选择历史或回放零执行副作用，不创建新尝试、不发送模型请求、不执行工具、不更新当前路由配置。

回放按当次记录展示；不重跑今天的路由算法解释过去。记录截断、事件断档、旧版本缺字段和历史只剩摘要时明确提示，不补造事件。重新发起任务或请求继续归原流程、当前资格和显式授权，本专题首版不增加该动作。

作用域切换清除旧视图并拒绝迟到响应；权限失效停止受保护读取。账号标识默认脱敏，角色只能查看其有权访问的记录；不传输原始 key、bearer、提供方凭据、模型正文或代码内容。开发页面使用正式 Web 的受权投影，不直接向浏览器开放可信 SDK 内部监听器。

图、列表、时间线共享所选请求身份。移动端保留可读的顺序列表及关键状态，原因和错误不能依赖悬停、颜色或动画；沿用语义 token、中英国际化及项目 UI 设计流程。

## 后置策略的研究范围

| 候选 | 进入条件 | 需要证明的约束 |
| --- | --- | --- |
| 会话 / 工具回合保持 | 有完整 SDK 往返与提供方缓存来源证据 | 当前开发尝试已有精确模型确认；优化不能在尝试内擅自换模型、账号或价格。跨尝试选择须重新核对并确认 |
| 价格优先 | 价格版本、单位、缓存口径与能力约束齐备 | 先确定获准且能力兼容的目标，再比较可解释成本；未知价格不按零价，低单价不推定总成本或质量更优 |
| 额度感知 | 厂商余额接口、刷新时效、权限和未知语义明确 | 不从应用 quota 推导厂商余额；陈旧数据和读取失败有明确处理，未知不伪装可用 |
| 速度 / 负载选择 | 同口径实测窗口、样本量、并发归因及失败数据齐备 | 不以一条缓存命中请求或非流式总耗时排名，不省略能力 / 授权检查 |
| 意图选模 | 明确任务分类、合适模型、分类质量与额外费用 / 延迟 / 数据授权 | 分类自身纳入预算和来源；分类失败行为须预先确认，不能静默降级质量或改变工具资格 |

这些候选未获得执行授权；未来如改变路由选择、重试、费用或凭据边界，先完成方案 / 兼容评审和范围确认，不从页面操作或账号存在推定批准。生产真实故障回退、账号生命周期、自动凭据导入、并行竞速和计费保持各自原停止线。

## 验收与收益判断

- 同一冻结记录下，图、文字、列表和账目一致；备用未派发、用量未知、工具仅入队均如实显示。
- 当前资格、配额、取消或类型化失败导致停止时，用户能从已有证据定位原因；未记录原因保持未知。
- 旧记录、断线重读、重复事件、断档、权限撤销、跨工作区及迟到响应不污染当前视图。
- 历史回放不触发模型、工具、预算或配置写入；日志、错误、导出和浏览器持久化不泄漏受保护材料。
- 先用固定响应与既有失败轨迹完成接口 / 消费 / 界面验证；真实提供方、真实模型效果、用户试用和生产验收另行登记。
- 实施前记录用户完成“定位实际目标、解释未切换、识别未知用量”的耗时、误判和求助点；交付后用同类任务比较，再决定是否投入策略优化。没有基线时不声明节省费用或提高排障效率。

普通呈现与只读消费复用现有 Go / Web 测试、构建和仓库门禁；有新协议 / 数据格式 / 外部风险时才补充相称验证。详细实施和视觉批准在进入对应阶段后登记。
