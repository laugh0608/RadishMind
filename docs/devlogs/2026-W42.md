## 2026-10-15 故障诊断应用前端一致性修复

### 范围与实现

项目所有者授权静态审查后修复两处前端问题，优先处理结果资产错配，再处理变量名编辑焦点；要求保持现有 API、权限和幂等语义，先完成单测、类型检查及必要仓库检查。首轮仅完成无服务验证；随后明确授权依次启动 Prompt、Agent 和结果证据隔离浏览器复验，每组通过并确认清理后进入下一组，结束更新记录并提交。本轮不调用真实模型，不推送。

- 结果错配的静态路径为：同一 Session 读取资产 A 后保存 B，旧实现只更新选中摘要，保留 A 的正文、运行链接与生命周期版本；标题与归档目标因此可能指向 B。现将选中摘要和详情收为同一审查状态，每次操作推进请求代次，新结果选中时取消旧读取并清空详情，迟到响应不能覆盖新选择；归档仅消费当前明确读取的同一资产及生命周期。列表筛选不重新应用旧保存回执，正文继续要求显式读取。
- 变量行旧 `key` 包含可编辑名称，逐字符改名会重建输入框并丢失焦点。现采用仅属于编辑器的稳定行标识，编辑、增删和服务端保存后的规范排序均保持对应行身份；恢复另一草案重新分配，既有请求序列化明确排除该标识。
- 新增状态回归覆盖已读 A → 保存 B、A 的迟到读取、重新选择同一资产的旧请求及生命周期归属；变量回归覆盖重命名后的保存排序、删除 / 新增 / 跨草案身份和真实试用素材五个样本的确定性预览。既有请求断言增加编辑器标识不进入 API 正文的检查。
- 既有 `workflow` 浏览器组登记三条新增流程：已读旧答案后保存新答案、忽略取消的延迟旧答案响应、诊断变量逐字符输入及保存恢复 / 五样本预览。结果用例核对显式精确读取、归档对象、筛选重载和运行链接；固定响应提供方仅增加可区分的第二份合成答案，不调用模型。未新增服务、依赖、API 或权限，也不改变客户端幂等键和保存语义。
